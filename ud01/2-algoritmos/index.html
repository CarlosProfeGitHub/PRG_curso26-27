    2. De la idea al algoritmo: piensa como un programador

    La programación es, en esencia, una forma sistemática de resolver problemas mediante ordenadores. Para que un problema sea resoluble por una computadora, debe poder expresarse de forma mecánica y automática, sin ambigüedades.

    ¿Por qué insistimos en el algoritmo?

    Porque programar no es escribir código, es resolver un problema. Escribir código sin un diseño previo produce programas que funciona "a medias" y que nadie —tampoco tú dentro de seis meses— entiende. En UD00 ya pracicaste esta fase con pseudocódigo; aquí la conectamos con el código real.

    2.1. Resolución de problemas: el método de Polya

    El matemático George Polya formuló un método heurístico de cuatro operaciones mentales para resolver problemas, que se alinea perfectamente con las fases del desarrollo de software:

    Fase del método de Polya Operación en programación Objetivo principal
    1. Entender el problema Analizar el problema Comprender qué se pide e identificar datos de entrada y resultados esperados.
    2. Trazar un plan Diseñar un algoritmo Encontrar una secuencia lógica de pasos para resolver el problema.
    3. Ejecutar el plan Codificar el programa Traducir el algoritmo diseñado a un lenguaje de programación (Java).
    4. Revisar Depurar y verificar Probar el programa con distintos casos para corregir fallos y optimizarlo.

    Reflexiona

    ¿En cuál de las cuatro fases fallamos más a menudo? La respuesta habitual es la 1: si no entendido bien el enunciado, todo lo demás está condemando.

    2.2. ¿Qué es un algoritmo?

    Un algoritmo es un conjunto de pasos o instrucciones lógicas, ordenadas y acotadas, diseñadas para resolver un problema o realizar una tarea.

    Ejemplo cotidiano. Los pasos para desayunar:

    Inicio
    Sentarse en la mesa
    Servir café con leche y azúcar
    Si tengo tiempo Entonces
        Mientras tenga apetito Hacer
            Untar mantequilla y mermelada en una tostada
            Comer la tostada
        Fin Mientras
    Fin Si
    Beber café con leche
    Levantarse
Fin

    Características fundamentales de un algoritmo

    • Generalidad: debe servir para resolver cualquier caso del problema (usando variables), no solo uno concreto.
    • Finitud: debe terminar obligatoriamente tras un número determinado de pasos.
    • Definibilidad: cada paso debe ser claro y no dar pie a dobles interpretaciones (sin ambigüedades).
    • Eficiencia: debe resolver el problema consumiendo el mínimo tiempo y recursos posibles.

    Algoritmo que no cumple las características

    • Sin generalidad: "Si la nota es 5,approved = true" → solo funciona con esa nota.
    • Sin finitud: "Repite hasta que se te ocurra" → nunca termina.
    • Sin definibilidad: "Haz lo que quieras con el número" → no se puede programar.

    2.3. Representación de algoritmos

    Los algoritmos son independientes de los lenguajes de programación y del hardware. Para diseñarlos antes de programar se utilizan principalmente dos métodos estructurados.

    Pseudocódigo

    Lenguaje descriptivo intermedio entre el lenguaje humano y el de programación. Ideal para estructurar la lógica sin preocuparse por la sintaxis estricta del compilador.

    Inicio
    Leer (A, B)
    Si (A > B) Entonces
        Escribir (B, A)
    SiNo
        Escribir (A, B)
    FinSi
Fin

    Diagrama de flujo

    Representación gráfica con símbolos estándar conectados por flechas que indican la secuencia de operaciones:

    Símbolo Significado
    ▭ Inicio / Fin (terminal)
    ▭ Entrada / Salida de datos
    ▭ Proceso / operación
    ◇ Decisión (condición)
    → Línea de flujo (sentido de lectura: de arriba abajo y de izquierda a derecha)

    El diagrama de flujo del pseudocódigo anterior (A y B ordenados de menor a mayor) sería: inicio → leer A, B → decisión ¿A > B? → sí: escribir B, A / no: escribir A, B → fin.

    Regla práctica

    Usa pseudocódigo para algoritmos con muchos cálculos; usa diagrama de flujo para algoritmos con muchas decisiones y bucles, porque la estructura visual se aprecia mejor.

    2.4. Algoritmos frente a programas

    Algoritmo Programa
    Naturaleza Lógica abstracta de la solución Implementación en un lenguaje concreto
    Lenguaje Independiente del lenguaje Java, C++, Python…
    Ejecución Lo ejecuta una persona Lo ejecuta el ordenador (JVM)
    Errores Difícil de detectar sin probarlo El compilador los detecta antes de ejecutar

    Cuando un problema es complejo aplicamos "divide y vencerás":

    • Diseño descendente (Top-Down): descomponer un problema grande en subproblemas más sencillos.
    • Diseño modular: resolver cada subproblema de forma independiente mediante módulos o subprogramas, para luego integrarlos.

    Puente con UD03

    Esa descomposición en módulos es exactamente lo que veremos en UD03 · Programación estructurada y modular, cuando introduzcamos los métodos de Java.
