    13. Trazas

    Actividades no obligatorias

    Las trazas tampoco son obligatorias. Guárdalas en ud03/trazas.

    ¿En qué consiste una traza?

    Leer un programa sin ejecutarlo, anotando el valor de cada variable en cada instrucción. En esta unidad hay que prestar especial atención a qué valor recibe cada parámetro y cuál es el valor devuelto por cada método.

    El método

    1. Dibuja una tabla por cada método que aparezca.
    2. Anota los valores de los parámetros en la entrada.
    3. Anota el valor de las variables locales en cada instrucción.
    4. Cuando encuentres una llamada a un método, escribe el valor devuelto antes de continuar.
    5. Si hay recursión, dibuja una fila por llamada.

    public static void modificar(int numero) {
    numero = numero * 10;
    System.out.println("Dentro:  " + numero);
}

public static void main(String[] args) {
    int valor = 5;
    System.out.println("Antes:   " + valor);
    modificar(valor);
    System.out.println("Después: " + valor);
}
    Solución 
    Antes:   5
Dentro:  50
Después: 5
    Momento valor (en main) numero (en modificar)
    Antes de la llamada 5 —
    Entrada al método 5 5 (copia)
    Tras numero *= 10 5 50
    Tras volver a main 5 (ya no existe)

    La línea clave es modificar(valor): se copia el valor antes de entrar. Cuando el método acaba, la copia se destruye.

    public static void copiar(int[] origen, int[] destino) {
    for (int i = 0; i < origen.length; i++) {
        destino[i] = origen[i];
    }
}

public static void main(String[] args) {
    int[] a = {1, 2, 3};
    int[] b = {9, 9, 9};

    copiar(a, b);
    System.out.println(a[0] + " " + b[0]);   // 1 1

    b[0] = 100;
    System.out.println(a[0] + " " + b[0]);   // 1 100
}
    Solución 
    1 1
1 100
    Momento a b
    Inicio [1, 2, 3] [9, 9, 9]
    Tras copiar(a, b) [1, 2, 3] [1, 2, 3]
    Tras b[0] = 100 [1, 2, 3] [100, 2, 3]

    En copiar, origen y destino reciben direcciones, no copias. El método escribe en el array real b.

    ¿Se puede evitar esto?

    Sí, haciendo una copia explícita del array:

    int[] copia = new int[a.length];
System.arraycopy(a, 0, copia, 0, a.length);

    Ahora sí hay dos arrays independientes.

    public static int contarMayores(int limite, int... numeros) {
    int contador = 0;
    for (int i = 0; i < numeros.length; i++) {
        if (numeros[i] > limite) {
            contador++;
        }
    }
    return contador;
}

public static void main(String[] args) {
    System.out.println(contarMayores(10, 5, 20, 30));
    System.out.println(contarMayores(10, 1, 2, 3));
    System.out.println(contarMayores(10));
}
    Solución 
    2
0
0
    Llamada numeros numeros.length Salida
    contarMayores(10, 5, 20, 30) [5, 20, 30] 3 2 (20 y 30)
    contarMayores(10, 1, 2, 3) [1, 2, 3] 3 0
    contarMayores(10) [] 0 0

    La llamada vacía es válida

    Con varargs, llamar sin argumentos crea un array vacío, no un null. Por eso el for no se ejecuta nunca y el resultado es 0. Si no usaras varargs y el for accedería a numeros[0], tendrías un ArrayIndexOutOfBoundsException.

    static final int POS_MINIMO = 0;
static final int POS_MAXIMO = 1;
static final int POS_MEDIA = 2;
static final int POS_TOTAL = 3;

public static int[] resumen(int[] datos) {
    int min = datos[0];
    int max = datos[0];
    int suma = 0;
    for (int i = 0; i < datos.length; i++) {
        if (datos[i] < min) min = datos[i];
        if (datos[i] > max) max = datos[i];
        suma += datos[i];
    }
    return new int[] {min, max, suma / datos.length, suma};
}

public static void main(String[] args) {
    int[] notas = {7, 3, 9, 5};
    int[] r = resumen(notas);
    System.out.println(r[POS_TOTAL]);
    System.out.println(r[POS_MAXIMO]);
    System.out.println(r[POS_MEDIA]);
}
    Solución 
    24
9
6
    i datos[i] min max suma
    0 7 7 7 7
    1 3 3 7 10
    2 9 3 9 19
    3 5 3 9 24

    El array devuelto es [3, 9, 24/4=6, 24]. Por eso r[POS_TOTAL] es 24, r[POS_MAXIMO] es 9 y r[POS_MEDIA] es 6.

    El error que cuesta un ejercicio entero

    Si en el return escribieras {min, suma / datos.length, max, suma} (intercambiando POS_MAXIMO y POS_MEDIA), el programa seguiría compilando y mostraría 24, 6, 9 en lugar de 24, 9, 6. Ningún compilador te avisa.

    static int total = 100;

public static void main(String[] args) {
    System.out.println(total);           // (1)

    {
        int total = 99;
        System.out.println(total);       // (2)
    }

    System.out.println(total);           // (3)

    Solución 
    100

100
    Línea Ámbito total
    (1) Clase 100
    (2) Bloque interno 99 (sombrea a la de clase)
    (3) Clase (el bloque ya terminó) 100

    Este código no compila si cambias el orden

    Lo que no es legal es declarar una local con el nombre de un parámetro del mismo método:

    public static void main(int total) {   // Parámetro llamado total
    int total = 99;                    // ❌ ERROR: variable total is already defined
}

    Java prohíbe el sombreado entre variables locales (y parámetros) del mismo método. Solo se puede ocultar una variable de clase. Ver §6.2.

    public static int f(int a) { return 1; }
public static int f(int a, int b) { return 2; }
public static int f(double a) { return 3; }
public static int f(int a, double b) { return 4; }

public static void main(String[] args) {
    System.out.println(f(1));          // (1)
    System.out.println(f(1, 2));       // (2)
    System.out.println(f(1.0));        // (3)
    System.out.println(f(1, 2.0));     // (4)
}
    Solución 
    1
2
3
4

    Java busca la versión que coincide exactamente con el tipo de cada argumento:

    Llamada Versión elegida Por qué
    f(1) f(int) Un argumento int → búsqueda exacta.
    f(1, 2) f(int, int) Dos int → coincidencia exacta.
    f(1.0) f(double) Un double → coincidencia exacta.
    f(1, 2.0) f(int, double) Un int y un double → coincidencia exacta.

    Por qué no hay ambigüedad

    Java elige exactamente la versión cuya firma coincide. Si ninguna coincidiera exactamente, buscaría la más cercana por conversión, y ahí es donde aparecerían las ambigüedades.

    public static void cuenta(int n) {
    System.out.print(n + " ");
    if (n > 0) {
        cuenta(n - 1);
    }
}

public static void main(String[] args) {
    cuenta(3);
}
    Solución 
    3 2 1 0

    Fíjate en que el println está antes del if, así que también se imprime el 0:

    Llamada Imprime ¿Llama recursivamente?
    cuenta(3) 3 Sí (3 > 0)
    cuenta(2) 2 Sí (2 > 0)
    cuenta(1) 1 Sí (1 > 0)
    cuenta(0) 0 No (0 > 0 es falso)
    ¿Y el caso base?

    Este método no tiene caso base típico: no devuelve nada, solo imprime. El if (n > 0) impide que la recursión siga, y por eso termina. Es recursión, pero no del tipo "calcular algo".

    public static int mcd(int a, int b) {
    if (b == 0) {
        return a;
    }
    return mcd(b, a % b);
}

public static void main(String[] args) {
    System.out.println(mcd(48, 18));
    System.out.println(mcd(17, 5));
}
    Solución 
    6
1

    Traza de mcd(48, 18) (algoritmo de Euclides):

    Llamada a b a % b Devuelve
    1.ª 48 18 12 → mcd(18, 12)
    2.ª 18 12 6 → mcd(12, 6)
    3.ª 12 6 0 → mcd(6, 0)
    4.ª 6 0 — Caso base → devuelve 6

    Por qué funciona

    El resto siempre es menor que el divisor, así que b va menguando: 18 → 12 → 6 → 0. Llega a 0 en un número finito de pasos. Esa es la garantía de terminación.

    public static int clasifica(int[] datos) {
    if (datos.length == 0) {
        return 0;
    }
    if (datos.length > 100) {
        return -1;
    }
    return datos[0];
}

public static void main(String[] args) {
    System.out.println(clasifica(new int[] {5, 6}));
    System.out.println(clasifica(new int[] {}));
    System.out.println(clasifica(new int[150]));
}
    Solución 
    5
0
-1
    Llamada datos.length Primera condición Segunda condición Devuelve
    clasifica({5, 6}) 2 2 == 0 → falso 2 > 100 → falso datos[0] = 5
    clasifica({}) 0 0 == 0 → cierto (no llega) 0
    clasifica(new int[150]) 150 150 == 0 → falso 150 > 100 → cierto −1

    El orden de las comprobaciones no es casual

    Si inviertieras las dos condiciones, clasifica({}) daría -1 en lugar de 0. La salida anticipada obliga a pensar en el orden: primero lo más frecuente o lo más simple, después las excepciones.
