    Antes de entregar cualquier actividad

    • La clase debe llamarse igual que el archivo .java.

    Bloque 3.1 · Métodos y procedimientos

    Actividad 01 · Tu primer método estático

    Escribe una clase Figuras con:

    1. Un procedimiento static void mostrarBienvenida(String nombre) que imprima Bienvenido, <nombre>.
    2. Una función static double areaRectangulo(double base, double altura) que devuelva base * altura.
    3. Una función static double perimetroRectangulo(double base, double altura) que devuelva 2 * (base + altura).

    El main pide la base y la altura, llama a los tres métodos y muestra los resultados.

    Solución orientativa 
    public class Figuras {
    public static void main(String[] args) {
        Scanner teclado = new Scanner(System.in);

        System.out.print("Tu nombre: ");
        String nombre = teclado.nextLine();

        System.out.print("Base: ");
        double base = teclado.nextDouble();

        System.out.print("Altura: ");
        double altura = teclado.nextDouble();

        mostrarBienvenida(nombre);
        System.out.println("Área      : " + areaRectangulo(base, altura));
        System.out.println("Perímetro : " + perimetroRectangulo(base, altura));

        teclado.close();
    }

    /** Imprime un mensaje de bienvenida. */
    public static void mostrarBienvenida(String nombre) {
        System.out.println("Bienvenido, " + nombre);
    }

    /** Devuelve el área de un rectángulo. */
    public static double areaRectangulo(double base, double altura) {
        return base * altura;
    }

    /** Devuelve el perímetro de un rectángulo. */
    public static double perimetroRectangulo(double base, double altura) {
        return 2 * (base + altura);
    }
}

    Comprueba los dos tipos de método

    • ¿Cuál de los tres métodos devuelve algo? ¿Cuál no?
    • ¿Qué pasaría si mostrarBienvenida tuviera double en lugar de void?

    Actividad 04 · Validación con salida anticipada

    Escribe static double areaTriangulo(double base, double altura) que devuelva el área del triángulo, o 0 si alguna medida no es positiva.

    Resuélvelo dos veces: una con un único return al final y otra con salida anticipada.

    Versión con salida anticipada 
    public static double areaTriangulo(double base, double altura) {
    if (base <= 0 || altura <= 0) {
        return 0;                    // Salida anticipada
    }
    return base * altura / 2;
}

    ¿Cuál se lee mejor?

    Ambas son correctas. Ahora añade una tercera condición: el triángulo debe tener además base != altura (no puede ser equilátero). ¿Sigues preferring la salida anticipada?

    Actividad 14 · Devolver varios valores

    Escribe static int[] dividir(int a, int b) que devuelva un array de dos posiciones: cociente y resto. Si b == 0, devuelve {0, 0}.

    1
2
3
    int[] resultado = dividir(17, 5);
System.out.println("Cociente: " + resultado[0]);
System.out.println("Resto:    " + resultado[1]);
    Solución 
    /**
 * Divide dos enteros.
 *
 * @param a dividendo
 * @param b divisor
 * @return un array de 2 posiciones: [cociente, resto].
 *         Si el divisor es 0, devuelve {0, 0}.
 */
public static int[] dividir(int a, int b) {
    if (b == 0) {
        return new int[] {0, 0};
    }
    return new int[] {a / b, a % b};
}

    Java sí permite que una variable local oculte a una variable de clase. ¿Qué imprime este programa?

    public class Sombras {
    static int numero = 100;                // Variable de clase

    public static void main(String[] args) {
        System.out.println(numero);         // (1)

        {
            int numero = 50;                // Local: SOMBREA a la de clase
            System.out.println(numero);     // (2)
        }

        System.out.println(numero);         // (3)
        muestra();
    }

    public static void muestra() {
        int numero = 7;                     // Local de otro método
        System.out.println(numero);         // (4)
    }
}
    Respuestas 
    100
50
100
7
    Línea Imprime Por qué
    (1) 100 Todavía no hay ninguna local que tape la de clase.
    (2) 50 La local del bloque interno sombrea a la de clase.
    (3) 100 El bloque terminó, así que vuelve a mandar la de clase.
    (4) 7 Otra local, en otro método. No tiene relación con las anteriores.

    Lo que Java NO permite

    Dos locales (o un parámetro y una local) del mismo método no pueden llamarse igual, aunque estén en bloques distintos:

    public static void main(String[] args) {
    int numero = 50;      // ❌ Si existiera otra local "numero" en un
    {                     //    bloque interior, daría error de compilación
        int numero = 99;  // ❌ ERROR: variable numero is already defined
    }
}

    El mensaje del compilador es variable numero is already defined in method main(String[]).

    La diferencia clave

    | | Legal | Ilegal | | :--- | :--- | | Local que oculta una variable de clase | ✅ Sí | | | Local que oculta un parámetro del mismo método | | ❌ No | | Local que oculta otra local del mismo método | | ❌ No |

    Lección

    El mismo nombre significa cuatro cosas distintas según dónde mires. Esto es legal, pero es exactamente lo que hace un código ilegible. Nunca declares una variable local con el nombre de un parámetro.

    Actividad 28 · Compara iterativo y recursivo

    Escribe las dos versiones y cronométralas:

    System.out.println(factorialRecursivo(10));
System.out.println(factorialIterativo(10));

    Después, prueba con 15, 16, 17 y 18.

    Qué observarás

    Ejecutando ambos métodos con estos valores obtienes exactamente lo mismo, porque los dos se desbordan en el mismo punto:

    n n! real Lo que imprime el programa (int)
    10 3 628 800 3628800
    12 479 001 600 479001600
    13 6 227 020 800 1932053504 ← desborda
    14 87 178 291 200 1278945280
    17 355 687 428 096 000 −288522240
    18 6 402 373 705 728 000 −898433024 
    El desbordamiento ocurre ya en **13!**, no en 17!: el máximo que cabe en un `int` es `2 147 483 647`, y `13! = 6 227 020 800` ya lo supera. A partir de ahí los valores salen **basura**: números negativos o positivos que no significan nada.

!!! tip "La conclusión importante"

    La recursividad **no es más rápida**. Aquí es peor: cada llamada guarda su copia de `n` en la pila. Usa bucles cuando el problema sea una acumulación, y `long` (o `double`) cuando el resultado pueda desbordar un `int`.

    Para `13!` necesitas un `long`; para `21!`, ni siquiera.

    Actividad 29 · Suma recursiva

    Escribe static int suma(int n) que devuelva la suma de los números del 1 al n.

    Predice en papel: ¿qué devuelve suma(1), suma(0) y suma(-3)?

    Respuesta
    • suma(1) → 1 (el caso base n <= 1 se cumple).
    • suma(0) → 1 (también cumple n <= 1).
    • suma(-3) → 1, pero por accidente: con n <= 1 el caso base se cumple a la primera. ¿Es ese el resultado que quieres para un negativo? Seguramente no lo que querías.

    Si el enunciado dice "números del 1 al n", un n negativo no debería devolver 1. Mejor así:

    public static int sumaSegura(int n) {
    if (n <= 0) {
        return 0;                   // Entrada no válida: 0
    }
    if (n == 1) {
        return 1;                   // Caso base
    }
    return n + sumaSegura(n - 1);
}

    Actividad 31 · Suma de los dígitos

    Escribe static int sumaDigitos(int numero) que sume las cifras de un número. Ejemplos:

    Entrada Salida Razonamiento
    1234 10 1 + 2 + 3 + 4
    999 27 9 + 9 + 9
    0 0 El número 0 no tiene cifras que sumar
    Pista clave

    El caso base es numero < 10: si el número tiene una sola cifra, se devuelve tal cual.

    public static int sumaDigitos(int numero) {
    if (numero < 0) {
        return sumaDigitos(-numero);       //ignoramos el signo
    }
    if (numero < 10) {
        return numero;                    // Caso base
    }
    return numero % 10 + sumaDigitos(numero / 10);
}

    La operación clave es numero % 10 (última cifra) y numero / 10 (resto de cifras): el problema se reduce a sí mismo con un número más pequeño.
