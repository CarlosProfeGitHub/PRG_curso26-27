    3. Métodos: firma, cuerpo y llamada

    En Java, todo vive dentro de una clase (ya lo estudiaste en la UD01) y todo el comportamiento se expresa mediante métodos. Un método es un bloque de código con nombre al que se puede llamar para que haga su trabajo.

    La idea en una frase

    Un método es una caja con nombre: le metes datos por un lado y te devuelve un resultado por el otro.

    3.1. Anatomía de un método

     
 
 
    public static double areaTriangulo(double base, double altura) {
    return base * altura / 2;
}
    Parte Nombre técnico Obligatorio Qué es
    public Modificador de acceso Sí (en Java) Indica quién puede llamar al método. public significa "cualquiera".
    static Modificador de método Sí en esta unidad Indica que el método pertenece a la clase, no a un objeto.
    double Tipo de retorno Sí Tipo de dato que devuelve. void si no devuelve nada.
    areaTriangulo Nombre del método Sí Por lo que se le llama. Se escribe en lowerCamelCase.
    (double base, double altura) Lista de parámetros No (puede ir vacía) Los datos que recibe: nombre y tipo de cada uno.
    { ... } Cuerpo del método Sí Las instrucciones que se ejecutan al llamarlo.

    static es obligatorio en esta unidad

    Todos los métodos que escribas aquí serán static. Explicarlo en detalle (y la diferencia con los métodos de instancia) es materia de UD06. Por ahora, la regla es simple:

    • static → el método se llama Clase.metodo(...), sin necesidad de crear ningún objeto.
    • No static → hace falta un objeto que "contenga" al método. Eso se ve en la UD06.

    3.2. Cómo se llama un método

    Una llamada tiene la forma:

    nombreDelMetodo(argumento1, argumento2, …);

    1
2
    double area = areaTriangulo(4.0, 6.0);
System.out.println("El área es " + area);   // El área es 12.0

    Los paréntesis no son opcionales

    Es el error de escritura más frecuente al empezar. Un método siempre se escribe con () detrás, aunque no tenga parámetros:

    System.out.println("Fin");          // ✅ println(...) es un método
System.out.print("Fin");            // ✅ sin salto de línea
System.out.print.ln("Fin");         // ❌ no existe: print y println son distintos

    Fíjate en que println y print son métodos de System.out. Hasta el main es un método.

    3.3. La firma y el orden de ejecución

    ¿Qué es la firma?

    La firma de un método es todo lo que hay antes del cuerpo: tipo de retorno, nombre y parámetros. Es lo que te permite saber si estás llamando al método correcto.

    static double areaTriangulo(double base, double altura)
└────────────────── FIRMA ──────────────────────────────────┘

    Dos métodos con firma distinta son métodos distintos, aunque se llamen igual (eso es la sobrecarga).

    Java ejecuta los métodos de arriba abajo

    A diferencia de la UD01, donde main tenía que ser la primera instrucción, aquí el orden de las líneas no importa: Java salta directamente al método que indicas y ejecuta su cuerpo entero.

    Lo que sí debe estar después de su uso

    Solo las variables locales. Si declaras una variable dentro de main y la usas en un método de abajo, no compila: la variable no existe allí. Ver §6.

    Por qué Math y Scanner ya te sonaban

    Sin saberlo, has usado métodos estáticos desde la UD01:

    Método Clase ¿Es un método estático?
    Math.pow(2, 3) java.lang.Math Sí
    Math.random() java.lang.Math Sí
    teclado.nextInt() java.util.Scanner No (necesita un objeto)
    System.out.println() java.lang.System Sí

    Math.PI y teclado.nextInt() se usan de forma distinta: el primero es un atributo estático y el segundo un método de instancia. En la UD06 se entiende la diferencia.

    /**
 * Calcula el área de un triángulo.
 *
 * @param base   base del triángulo
 * @param altura altura del triángulo
 * @return el área, o 0 si alguna medida no es positiva
 */
public static double areaTriangulo(double base, double altura) {
    if (base <= 0 || altura <= 0) {
        return 0;
    }
    return base * altura / 2;
}

    Falta el return

    El compilador no te deja salir de un método con tipo de retorno sin devolver nada:

    1
2
3
4
    public static int sumar(int a, int b) {
    int resultado = a + b;
    // Falta return: error "missing return statement"
}

    Es una de las pocas ayudas que da el compilador de Java, y es muy valiosa. Si te aparece este error, mira qué camino del if puede llegar al final sin devolver nada.
