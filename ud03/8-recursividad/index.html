    8. Recursividad

    Hasta ahora has resuelto los problemas iterando: un bucle repite instrucciones. Existe otra forma de repetir: el método se llama a sí mismo. Es lo que se conoce como recursividad.

    Definición

    La recursividad es una forma de describir un proceso de manera que, a lo largo de esa descripción, se usa el proceso mismo que se está describiendo, pero aplicado a un caso más simple.

    8.1. La analogía de las muñecas rusas

    Una muñeca rusa contiene otra más pequeña, que contiene otra más pequeña… hasta que la más pequeña ya no contiene ninguna.

    El proceso "abrir una muñeca rusa" se describe usando el proceso "abrir una muñeca rusa", pero aplicado a un objeto más pequeño. Eso es recursividad.

    El Sistema Operativo GNU

    Se define a sí mismo: GNU significa "GNU is Not Unix". El nombre usa el propio concepto que quiere definir. Algo parecido ocurre con W3C o con las unidades de medida anglosajonas (un pie son 12 pulgadas, una yarda son 3 pies).

    8.2. La analogía del juego de adivinar

    Imagina que tengo un número secreto entre 0 y 100 y solo puedes preguntar si es mayor o menor. La estrategia óptima es:

    Prueba primero el 50. Si no has acertado y el número es más alto, busca entre 51 y 100. Si es más bajo, busca entre 0 y 49. Para cada caso, vuelve a probar el valor que hay en el centro del nuevo intervalo. Y así sucesivamente, hasta adivinarlo.

    Fjate en el detalle: el proceso de adivinar se basa en el proceso de adivinar. Parece trampa, porque es como definir una palabra con la propia palabra. Pero hay un elemento clave:

    Llamada Valores posibles Tamaño
    1.ª entre 0 y 100 101
    2.ª entre 51 y 100 (o 0 y 49) 50
    3.ª la mitad del intervalo anterior 25
    … … …
    Última 1 valor 1

    El proceso se repite sobre un caso cada vez más pequeño, y eso es lo que garantiza que termine.

    8.3. Un método recursivo tiene dos casos

    Un método recursivo es aquel que, dentro de su bloque de instrucciones, contiene una llamada a sí mismo.

    Todo método recursivo se estructura SIEMPRE con una selección múltiple (como un if-else) que contiene estos dos casos:

    Caso Qué es Cuándo se ejecuta Contiene una llamada recursiva
    Caso base El problema ya es suficientemente simple para resolverse directamente. Cuando los parámetros llegan al "final". NO
    Caso recursivo El problema aún se puede reducir. Cuando los parámetros aún son "grandes". SÍ

    Los dos casos son obligatorios

    • Sin caso base → el método se llama a sí mismo para siempre hasta agotar la memoria (StackOverflowError).
    • Sin caso recursivo → el método no es recursivo: solo repite el caso base.

    Y hay una tercera regla, la más difícil de ver:

    • El caso recursivo debe acercarse al caso base, cambiando el valor del parámetro. Si la llamada recursiva se hace con el mismo valor, el método nunca termina.

    8.4. El factorial: ejemplo paso a paso

    El factorial de un entero positivo es la multiplicación de todos los números desde el 1 hasta ese número:

    7! = 1 × 2 × 3 × 4 × 5 × 6 × 7 = 5040

    ¿Cómo se define el factorial recursivamente?

    Mira el factorial de 4 y separa el último factor:

    4! = 1 × 2 × 3 × 4
4! = (1 × 2 × 3) × 4
4! = 3! × 4

    Y de aquí sale la definición:

    CASO BASE:     0! = 1
CASO RECURSIVO: n! = n × (n - 1)!

    Fíjate en el detalle clave

    En la definición recursiva, (n - 1)! es el mismo factorial, pero de un número menor. El 4 se reduce al 3, el 3 al 2, el 2 al 1, el 1 al 0… y el 0 es el caso base.

    8.5. La traza completa del factorial de 4

    Antes de ver el código, entiende cómo se ejecuta. Esta traza es el corazón de la recursividad.

    Llamada Expresión Implementación Qué ocurre
    1.ª 4! 4 × (3)! El 4 espera. Se evalúa factorial(3)
    2.ª — 4 × 3 × (2)! El 3 espera. Se evalúa factorial(2)
    3.ª — 4 × 3 × 2 × (1)! El 2 espera. Se evalúa factorial(1)
    Caso base — 4 × 3 × 2 × (1) ¡Llega el caso base! factorial(1) = 1
    Retorno — 4 × 3 × 2 × 1 24

    La fase de descenso y la fase de retorno

    Este es el concepto más importante de toda la unidad:

    1. Fase de descenso (o de desenrollado): se hacen las llamadas recursivas una detrás de otra, apilando cada una su propio n. Se ejecuta la línea del if de cada llamada, y el return del caso recursivo todavía no ha ocurrido.
    2. Fase de retorno (o de desempilado): se llega al caso base y se empieza a volver. Cada return pendiente se va ejecutando y va multiplicando el resultado.
    Momento Qué ocurre Pila de llamadas
    Entrada Se llama a factorial(4) factorial(4)
    Iteración 1 Se llama a factorial(3) factorial(4) → factorial(3)
    Iteración 2 Se llama a factorial(2) factorial(4) → factorial(3) → factorial(2)
    Iteración 3 Se llama a factorial(1) … → factorial(1)
    Caso base 1! = 1 …desapila
    Retorno 1 2! = 2 × 1 = 2 …desapila
    Retorno 2 3! = 3 × 2 = 6 …desapila
    Retorno 3 4! = 4 × 6 = 24 Vacía

    Nunca te saltes la fase de descenso

    Un error conceptual muy común es pensar que el cálculo se hace "de arriba abajo". No es así: el 4 no se multiplica hasta que la llamada factorial(3) haya terminado de devolver. Por eso la multiplicación aparece en la fase de retorno, no en la de descenso.

    Sobre la definición matemática y el código

    Matemáticamente el factorial se define con 0! = 1. El código de abajo usa n == 0 || n == 1 como caso base, así que en la práctica la cadena termina en factorial(1) y no en factorial(0). Las dos cosas son correctas: cambiar el caso base a n == 0 alargaría la traza una llamada más, pero daría el mismo resultado.

    /**
 * Calcula el factorial de un número entero de forma recursiva.
 *
 * @param n número entero no negativo
 * @return el resultado de n!
 */
public static int factorial(int n) {

    // ---------- CASO BASE ----------
    if (n == 0 || n == 1) {
        System.out.println("Caso base: factorial(" + n + ") = 1");
        return 1;
    }

    // ---------- CASO RECURSIVO ----------
    System.out.println("Caso recursivo: " + n + "! = " + n + " * factorial(" + (n - 1) + ")");
    int resultado = n * factorial(n - 1);        // Aquí se llama a sí mismo

    System.out.println("  vuelve de factorial(" + (n - 1) + ") -> factorial(" + n + ") = " + resultado);
    return resultado;
}
    Salida real de factorial(4) 
    Caso recursivo: 4! = 4 * factorial(3)
Caso recursivo: 3! = 3 * factorial(2)
Caso recursivo: 2! = 2 * factorial(1)
Caso base: factorial(1) = 1
  vuelve de factorial(1) -> factorial(2) = 2
  vuelve de factorial(2) -> factorial(3) = 6
  vuelve de factorial(3) -> factorial(4) = 24

    Observa el orden de las líneas: los tres "Caso recursivo" salen primero y en orden descendente (4, 3, 2); el "Caso base" sale después; y solo entonces empiezan los retornos, en orden ascendente (2, 3, 4).

    Lee las líneas de abajo arriba

    Los tres últimos números de la salida son 2, 6 y 24. Si los lees de abajo arriba, son las multiplicaciones 2 × 1, 3 × 2 y 4 × 6. Eso es exactamente la fase de retorno.

    Cambiar n - 1 por n es el error más grave

    public static int factorial(int n) {
    if (n == 0) {
        return 1;
    }
    return n * factorial(n);        // ❌ Bucle infinito: se llama con el MISMO valor
}

    El método se llamaría a sí mismo infinitas veces con el mismo argumento hasta agotar la pila. El programa se cuelga y acaba dando un StackOverflowError.

    Pregunta de control antes de entregar cualquier recursión

    ¿Con qué valor se llama al método en el caso recursivo?

    Si la respuesta es "con el mismo valor", no has terminado. Debe acercarse al caso base.

    8.7. Factorial iterativo frente a factorial recursivo

    El mismo resultado se puede obtener con un bucle:

    public static int factorialIterativo(int n) {
    int resultado = 1;
    for (int i = 2; i <= n; i++) {
        resultado *= i;
    }
    return resultado;
}
    Iterativo Recursivo
    Código Más corto y directo Más corto, pero hay que entenderlo
    Memoria Solo las variables locales Una pila con una copia por llamada
    Velocidad Más rápido (menos llamadas) Más lento por la sobrecarga de la pila
    Legibilidad Muy clara para problemas aritméticos Clara para problemas que se dividen

    Regla práctica para elegir

    Usa recursividad cuando… Usa bucles cuando…
    El problema se divide naturalmente en subproblemas del mismo tipo El problema es una simple acumulación
    La estructura del dato es jerárquica (árboles, carpetas, figuras) Solo necesitas contar o sumar
    Te cuesta más escribir el for que el if El bucle te resulta más claro

    Para el factorial, el bucle es claramente mejor. La recursividad brilla en §9.2, con la búsqueda binaria.
