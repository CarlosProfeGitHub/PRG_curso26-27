    4. Procedimientos y funciones

    En la UD02 ejecutabas un programa de principio a fin. Aquí, cada fragmento de programa devuelve algo. No todos los métodos devuelven un valor, y esa es exactamente la distinción entre un procedimiento y una función.

    La idea en una frase

    Una función te da un resultado; un procedimiento te da un efecto secundario (normalmente, mostrar algo por pantalla).

    4.1. Procedimiento (void): hace, no devuelve

    Un procedimiento (o método void) ejecuta su trabajo y no devuelve ningún valor. Su único efecto es lo que hace por dentro: normalmente, imprimir.

    1
2
3
    public static void mostrarSaludo(String nombre) {
    System.out.println("Hola, " + nombre + "!");
}

    void significa "sin valor de retorno", NO "sin efecto"

    Un método void sí puede hacer cosas: imprimir, modificar un array, escribir en un fichero. Lo que no puede es devolver un resultado con return valor;.

    public static void imprimirLinea(int numero) {
    // Con void solo se permite "return;" para salir, sin valor
    if (numero < 0) {
        return;                        // ✅ salida temprana
    }
    System.out.println("Línea " + numero);
}

    public static void imprimirLinea(int numero) {
    if (numero < 0) {
        return 1;                      // ❌ ERROR: "int cannot be converted to void"
    }
}

    4.2. Función: devuelve un valor

    Una función devuelve un resultado que el llamante puede guardar, comparar o imprimir.

    1
2
3
    public static int sumar(int a, int b) {
    return a + b;
}

    Y así se usa:

    1
2
3
4
5
    int resultado = sumar(3, 7);
System.out.println(resultado);            // 10

// Se puede usar directamente en una expresión
System.out.println("La suma es " + sumar(3, 7));

    La diferencia real está en cómo se usa

    Procedimiento (void) Función (con retorno)
    Sintaxis void Un tipo (int, double, String…)
    Devuelve Nada Un valor
    Se usa así mostrarSaludo("Ana"); int r = sumar(3, 7);
    Efecto Efecto secundario (imprimir) Un valor reutilizable
    Se puede encadenar No Sí 
    // Un procedimiento: efecto directo
mostrarLinea(5);

// Una función: el valor se puede seguir usando
int total = sumar(sumar(2, 3), sumar(4, 5));   // 14

    4.3. El return en detalle

    La sentencia return hace dos cosas a la vez:

    1. Devuelve el valor al llamante.
    2. Termina el método. Nada de lo que haya después se ejecuta.
    1
2
3
4
5
6
7
8
9
    public static String clasificaEdad(int edad) {
    if (edad < 0) {
        return "Edad inválida";      // Sale aquí. La línea 7 NO se ejecuta.
    }
    if (edad < 18) {
        return "Menor de edad";
    }
    return "Mayor de edad";
}

    El return solo devuelve un valor

    Si necesitas devolver dos o más resultados, tienes tres opciones:

    Opción 1 · Devolver una cadena formateada.

    public static String divisionEntera(int a, int b) {
    if (b == 0) {
        return "No se puede dividir entre cero";
    }
    return "Cociente: " + (a / b) + " | Resto: " + (a % b);
}

    Opción 2 · Devolver un array. Es la más limpia.

    public static int[] divisionEntera(int a, int b) {
    if (b == 0) {
        return new int[] {-1, -1};        // Un valor de error
    }
    return new int[] {a / b, a % b};       // cociente, resto
}

    Opción 3 · Usar parámetros modificables. Se explica en el §5.5.

    La opción 2 es la recomendada

    Los arrays aún no se han visto en profundidad (eso es la UD04), pero una función que devuelve varios datos necesita un array o un objeto. Cuando llegue esa unidad, esta solución tendrá todo el sentido.

    4.4. Reglas de oro del return

    Regla Explicación
    Todo camino debe devolver Si el tipo de retorno no es void, el compilador exige un return en todos los caminos.
    Menos return, mejor Se recomienda uno solo al final, o usar la salida anticipada si hay muchos.
    El valor debe ser compatible Con el tipo declarado: no puedes devolver un String en un método int.
    Después de un return hay código muerto Lo que va después nunca se ejecuta.

    Patrón A · Un solo return al final

    public static double perimetro(double radio) {
    double resultado;

    if (radio > 0) {
        resultado = 2 * Math.PI * radio;
    } else {
        resultado = 0;
    }

    return resultado;
}

    Patrón B · Salida anticipada

    Cuando hay muchos casos, la salida anticipada es más legible:

    1
2
3
4
5
6
    public static double perimetro(double radio) {
    if (radio <= 0) {
        return 0;                            // Sale en el caso no válido
    }
    return 2 * Math.PI * radio;              // Y solo queda el camino bueno
}

    Cuál usar

    Con dos o tres caminos, ambos patrones valen. A partir de cuatro o cinco caminos, la salida anticipada gana en claridad: cada caso exceptional se resuelve en dos líneas y el resto del método no está indentado.

    Puente con UD02

    La salida anticipada es exactamente el return que ya usaste en las trazas de UD02 y en las actividades donde validabas la entrada del usuario. Aquello era un if en main; aquí es un if dentro de un método, y por eso es aún más útil.
