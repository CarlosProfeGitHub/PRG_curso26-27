    6. Ámbito de las variables

    El ámbito (o scope) es la zona del programa donde una variable existe y se puede usar. Hasta ahora solo usaste variables locales, pero en cuanto añades métodos, las reglas se complican.

    La idea en una frase

    Una variable existe desde donde se declara hasta el final del bloque { } que la contiene. Y fuera de ese bloque, deja de existir.

    6.1. Los tres niveles de variables

    Nivel Dónde se declara Dónde se puede usar Ejemplo
    Parámetro En la firma del método Solo dentro de ese método double base
    Variable local En el cuerpo del método Desde la declaración hasta el final del método int contador = 0;
    Variable de clase (static) Fuera de los métodos En todos los métodos de la clase static int total;

    public class Ambito {

    static int totalOperaciones = 0;   // Variable de CLASE: visible en toda la clase

    public static void main(String[] args) {
        int resultado = sumar(3, 7);    // Variable LOCAL de main
        System.out.println(resultado);  // ✅ Existe

        System.out.println(totalOperaciones);   // ✅ Existe
    }

    public static int sumar(int a, int b) {     // a y b son PARÁMETROS
        int parcial = a + b;                    // Variable LOCAL de sumar
        totalOperaciones++;                     // ✅ Accede a la de clase
        return parcial;
    }
}

    Es el mismo concepto que estudiaste en el §2.4 de la UD02, pero ahora aplicado a los métodos.

    El orden de declaración también importa

    int x = 5;
System.out.println(y);   // ❌ Todavía no se ha declarado
int y = 10;

    A diferencia de los métodos (que pueden estar en cualquier orden), las variables deben declararse antes de usarse. No existe el "salto" que sí hay con las llamadas a métodos.

    6.2. El sombreado (shadowing)

    Cuando declaras una variable local con el mismo nombre que una variable de clase, la nueva variable oculta a la anterior mientras dure su bloque. Esto se llama sombreado.

    public class Sombras {

    static int total = 100;                  // Variable de clase

    public static void main(String[] args) {
        System.out.println(total);           // 100: no hay local que la tape

        {
            int total = 99;                  // Esta local SÍ la sombrea
            System.out.println(total);       // 99
        }

        System.out.println(total);           // 100: vuelve a mandar la de clase
    }
}
    Momento total vale
    Dentro del bloque interno 99
    Fuera del bloque interno 100 (la variable de clase)

    Pero con un parámetro NO se puede

    Si el método recibe un parámetro llamado total, ya no puedes declarar una local con ese mismo nombre en ningún bloque del método:

    static int total = 100;

public static void ejemplo(int total) {   // El parámetro ocupa el nombre
    {
        int total = 99;                   // ❌ ERROR: variable total is already defined
        System.out.println(total);
    }
}

    El mensaje del compilador es variable total is already defined in method ejemplo(int).

    La regla real de Java

    Se puede… Se puede…
    ✅ Una local con el mismo nombre que una variable de clase ✅ Dos parámetros de métodos distintos con el mismo nombre
    ✅ Una local con el mismo nombre que una variable de clase en un método distinto ❌ Una local con el mismo nombre que un parámetro del mismo método
    ❌ Dos locales del mismo método, aunque estén en bloques anidados

    Compruébalo tú mismo

    Ni siquiera esto compila, aunque el bloque interno esté claramente separado:

    int x = 1;
{
    int x = 2;      // ❌ ERROR: variable x is already defined
}

    A diferencia de C++ o JavaScript, Java prohíbe por completo el sombreado entre locales del mismo método.

    Regla del curso

    Cuando un parámetro te estorbe, cambia el nombre de la variable local, no intentes repetir el del parámetro:

    // ❌ No compila
public static int area(double base) {
    double base = 5;      // ¡El parámetro ya existe!
}

// ✅ Claro
public static double precioConIVA(double precio, double tipoIVA) {
    double baseImponible = precio;
    return baseImponible + baseImponible * tipoIVA / 100;
}

    6.3. Variables de clase: cuándo usarlas

    Una variable static es compartida por toda la clase. Todos los métodos ven la misma variable.

    public class ContadorGlobal {

    static int llamadas = 0;               // Compartida por toda la clase

    public static void ejecutar() {
        llamadas++;                        // Incrementa la misma variable
        System.out.println("Llamadas: " + llamadas);
    }

    public static void main(String[] args) {
        ejecutar();                        // Llamadas: 1
        ejecutar();                        // Llamadas: 2
        ejecutar();                        // Llamadas: 3
        System.out.println("Total: " + llamadas);   // Total: 3
    }
}

    Úsala para: constantes

    El uso principal en esta unidad son las constantes, que no cambian nunca:

    public class Conversion {
    static final double PESETAS_POR_EURO = 166.386;
    static final int MAXIMO_INTENTOS = 3;

    public static double aPesetas(double euros) {
        return euros * PESETAS_POR_EURO;
    }
}
    Convención Significado
    static Pertenece a la clase, no a un objeto.
    final No se puede modificar después de inicializarse.
    NOMBRE_EN_MAYUSCULAS Convención para constantes.

    Úsala con cuidado para: contadores globales

    Una variable de clase compartida es potente pero peligrosa: cualquier método puede cambiarla sin que el llamante lo sepa. En programas grandes eso genera errores difíciles de encontrar.

    ¿Es buen sitio para una variable de clase?
    ✅ Una constante (static final)
    ✅ Un contador de uso dentro de la clase
    ❌ Un valor que solo le interesa a un método
    ❌ Un valor que debería ser independiente en cada método

    Regla práctica

    Si dudas, usa una variable local. Es más fácil de razonar y no tiene efectos colaterales. Promote a variable de clase solo cuando dos o más métodos necesiten compartir ese valor.

    }

    System.out.println(suma);   // ❌ "variable suma might not have been initialized"

    La solución es inicializar con el valor neutro

    Dale un valor por defecto antes de la estructura de control. Es más rápido y evita el error:

    int suma = 0;               // ✅ Siempre tiene valor

    El compilador te está avisando de algo real: existe un camino en el que suma no tiene valor válido. Fíjate en el mensaje: es tu aliado, no tu enemigo.
