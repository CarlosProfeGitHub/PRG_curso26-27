    2. Programación estructurada y modular

    Hasta ahora has escrito programas que caben en un main. En cuanto un programa pasa de unas 30 líneas, deja de caber en la cabeza de quien lo escribe y de quien lo lee. Esta unidad es el salto de programar a diseñar programas.

    La idea en una frase

    En vez de un programa gigante, escribir muchos programas pequeños que se llaman entre sí.

    public class ProgramaGigante {
    public static void main(String[] args) {
        Scanner teclado = new Scanner(System.in);

        System.out.print("Introduce la base: ");
        double base = teclado.nextDouble();

        System.out.print("Introduce la altura: ");
        double altura = teclado.nextDouble();

        double area;
        if (base > 0 && altura > 0) {
            area = base * altura / 2;
        } else {
            area = 0;
        }

        System.out.print("Introduce el radio: ");
        double radio = teclado.nextDouble();

        double perimetro;
        if (radio > 0) {
            perimetro = 2 * Math.PI * radio;
        } else {
            perimetro = 0;
        }

        System.out.print("Introduce el lado: ");
        double lado = teclado.nextDouble();

        double volumen;
        if (lado > 0) {
            volumen = Math.pow(lado, 3);
        } else {
            volumen = 0;
        }

        System.out.println("Área      : " + area);
        System.out.println("Perímetro : " + perimetro);
        System.out.println("Volumen   : " + volumen);

        teclado.close();
    }
}
    Problema Consecuencia
    Repetición La comprobación if (x > 0) aparece tres veces, idéntica.
    Mezcla de responsabilidades El programa lee datos, valida, calcula e imprime. Son cuatro tareas distintas.
    Ilegibilidad Para cambiar el cálculo del área, hay que leer 60 líneas para no romper nada.
    Imposible de reutilizar El cálculo del área está atrapado dentro del main. No se puede usar en otro programa.

    import java.util.Scanner;

public class Figuras {

    public static void main(String[] args) {
        Scanner teclado = new Scanner(System.in);

        System.out.print("Introduce la base: ");
        double base = teclado.nextDouble();

        System.out.print("Introduce la altura: ");
        double altura = teclado.nextDouble();

        System.out.print("Introduce el radio: ");
        double radio = teclado.nextDouble();

        System.out.print("Introduce el lado: ");
        double lado = teclado.nextDouble();

        System.out.println("Área      : " + areaTriangulo(base, altura));
        System.out.println("Perímetro : " + perimetroCirculo(radio));
        System.out.println("Volumen   : " + volumenCubo(lado));

        teclado.close();
    }

    /** Devuelve el área de un triángulo, o 0 si las medidas no son válidas. */
    public static double areaTriangulo(double base, double altura) {
        if (base <= 0 || altura <= 0) {
            return 0;
        }
        return base * altura / 2;
    }

    /** Devuelve el perímetro de un círculo, o 0 si el radio no es válido. */
    public static double perimetroCirculo(double radio) {
        if (radio <= 0) {
            return 0;
        }
        return 2 * Math.PI * radio;
    }

    /** Devuelve el volumen de un cubo, o 0 si el lado no es válido. */
    public static double volumenCubo(double lado) {
        if (lado <= 0) {
            return 0;
        }
        return Math.pow(lado, 3);
    }
}

    El main ahora solo lee datos y muestra resultados: toda la lógica se ha ido a los métodos.

    Antes Después
    44 líneas, un solo bloque 14 líneas de main + 3 métodos cortos
    Validación repetida 3 veces Validación dentro de cada método
    El área no se puede reutilizar areaTriangulo(4, 6) sirve en cualquier programa

    Cómo leer un programa modular

    Empieza siempre por main: es el índice del programa. Desde ahí, salta a cada método que se llame y lee qué hace. Los métodos nunca se ejecutan solos.

    2.3. Los principios que guían el troceado

    Cuando no se te ocurra cómo dividir un programa, aplica estos tres criterios.

    2.3.1. Un método, una responsabilidad

    Cada método debería resolver un problema. Si al describirlo en una frase necesitas la palabra "y" ("calcula el área y la comprueba y la muestra"), es que son varios métodos.

    // ❌ Tres responsabilidades
public static void procesarTriangulo() {
    // lee datos, valida, calcula y muestra
}

    // ✅ Una responsabilidad cada uno
public static double areaTriangulo(double base, double altura) { ... }
public static boolean medidasValidas(double base, double altura) { ... }
public static void mostrarArea(double area) { ... }

    2.3.2. Entrada → proceso → salida

    La estructura que ya usabas dentro de un programa, ahora dentro de cada método:

    public static double perimetroCirculo(double radio) {
    // Entrada: el parámetro radio
    if (radio <= 0) {
        return 0;              // Salida temprana
    }
    // Proceso
    double perimetro = 2 * Math.PI * radio;
    // Salida
    return perimetro;
}

    Un método NO debe leer del teclado

    Un método que hace teclado.nextInt() no se puede probar ni reutilizar. Quien lee los datos es siempre main (o un método que recibe un Scanner como parámetro). El método recibe datos por parámetros y devuelve el resultado.

    // ❌ El método depende del teclado: imposible de probar
public static double pedirYCalcularArea() {
    Scanner teclado = new Scanner(System.in);
    double base = teclado.nextDouble();
    return base * 5;
}

// ✅ El método es independiente: se puede probar con cualquier dato
public static double areaRectangulo(double base, double altura) {
    return base * altura;
}

    2.3.3. Alta cohesión y bajo acoplamiento

    Principio Qué significa
    Alta cohesión Un método resuelve una cosa. Todo su código está relacionado.
    Bajo acoplamiento Un método no depende de lo que hace el resto del programa. Cambiar main no obliga a cambiar el método.

    Acoplamiento en la práctica

    // ❌ Alto acoplamiento: depende de una variable global de main
static double precioFinal;

public static double conIVA(double precio) {
    return precio * 1.21;      // El 21 % está "escondido" en el código
}

    // ✅ Bajo acoplamiento: toda la información que necesita está en su firma
public static double conIVA(double precio, double tipoIVA) {
    return precio + precio * tipoIVA / 100;
}

    El segundo se puede probar con cualquier IVA, se entiende leyendo la firma, y no se rompe si mañana el impuesto cambia al 25 %.

    2.4. Programación estructurada frente a modular

    Concepto Definición Responde a…
    Programación estructurada Un programa se compone de tres estructuras de control (secuencia, selección e iteración) con un solo punto de entrada y un solo punto de salida. ¿Cómo se ejecuta el programa?
    Programación modular Un programa se divide en módulos (en Java, métodos) que se comunican entre sí. ¿Cómo se organiza el programa?

    Las dos cosas van juntas

    La programación modular es "dónde meto este trozo de código". La estructurada es "cómo se ejecuta este trozo de código". Un método se escribe con las tres estructuras de la UD02, y un programa se organiza en muchos métodos.

    No es una cosa nueva: es la UD02 hecha reutilizable.

    Puente con el resto del curso

    • La descomposición de un problema en subproblemas es lo que ya viste en el §2.4 de la UD01, aplicado ahora al código.
    • La modularidad es uno de los principios de la POO que verás en UD06: allí los métodos passports a tener objetos y sus datos. Aquí todos serán estáticos.
