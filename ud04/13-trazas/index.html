    13. Trazas

    Actividades no obligatorias

    Las trazas tampoco son obligatorias. Guárdalas en ud04/trazas.

    ¿En qué consiste una traza?

    Leer un programa sin ejecutarlo, anotando el valor de cada componente del array en cada instrucción. En esta unidad lo que más se complica es el estado del array y el índice del bucle al mismo tiempo.

    El método

    1. Escribe el array con su contenido inicial.
    2. Para cada vuelta del bucle, anota el valor de i y el valor al que apunta array[i].
    3. Si el array se modifica (un intercambio, un fill), reescribe el array entero después de esa instrucción.
    4. Marca qué celda de la tabla estás mirando: los errores de recorrido vienen de mirar la posición equivocada.

    int[] v = {4, 7, 1};
int suma = 0;
int maximo = v[0];

for (int i = 0; i < v.length; i++) {
    suma += v[i];
    if (v[i] > maximo) {
        maximo = v[i];
    }
}

System.out.println(suma + " " + maximo);
    Solución 
    12 7
    i i < 3 v[i] suma maximo
    Inicio — — 0 4
    0 sí 4 0 + 4 = 4 4 > 4? no → 4
    1 sí 7 4 + 7 = 11 7 > 4? sí → 7
    2 sí 1 11 + 1 = 12 1 > 7? no → 7
    3 no — Sale del bucle

    El detalle que cambia el resultado

    El máximo no se inicializa con 0, sino con v[0]. Si se inicializara con 0 y todos los valores fueran negativos, el resultado sería 0 en lugar del máximo real.

    Traza 02 · El recorrido descendente

    1

    int[] v = {2, 5, 3};
int total = 0;

for (int i = v.length - 1; i >= 0; i--) {
    total = total * 10 + v[i];
}

System.out.println(total);
    Solución 
    352
    i i >= 0 v[i] total = total * 10 + v[i]
    Inicio — — 0
    2 sí 3 0 * 10 + 3 = 3
    1 sí 5 3 * 10 + 5 = 35
    0 sí 2 35 * 10 + 2 = 352
    −1 no — Sale del bucle

    ¿Y con i > 0 en lugar de i >= 0?

    Imprimiría 35, porque el primer elemento del array (v[0]) se saltaría. Es el error clásico del recorrido descendente.

    int[] datos = {5, 8, 3, 9, 0, 7};
int i = 0;
boolean encontrado = false;

while (i < datos.length && !encontrado) {
    if (datos[i] == 0) {
        encontrado = true;
    } else {
        i++;
    }

    Solución 
    true 4
    Vuelta i i < 6 !encontrado datos[i] Acción i final
    1.ª 0 sí sí 5 no es 0 → i++ 1
    2.ª 1 sí sí 8 no es 0 → i++ 2
    3.ª 2 sí sí 3 no es 0 → i++ 3
    4.ª 3 sí sí 9 no es 0 → i++ 4
    5.ª 4 sí sí 0 es 0 → encontrado = true 4

    La condición del while se evalúa antes de cada vuelta. En la 6.ª vuelta, !encontrado ya es false, así que el bucle termina sin mirar datos[4] otra vez.

    int[] datos = {5, 8, 3, 9};
int i = 0;

while (i < datos.length && datos[i] != 0) {
    i++;

    System.out.println("Hay un cero en la posición " + i);

    System.out.println("No hay ningún cero");

    Solución

    No imprime nada: el programa lanza una excepción antes de llegar al if.

    Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException: Index 4 out of bounds for length 4
    at Traza04.main(Traza04.java:7)
    Momento i datos[i]
    Vuelta 1 0 5 → i = 1
    Vuelta 2 1 8 → i = 2
    Vuelta 3 2 3 → i = 3
    Vuelta 4 3 9 → i = 4
    Comprobación 4 4 < 4 es falso → sale del bucle
    Línea 6 4 💥 datos[4] no existe

    El fallo está en la línea resaltada

    La comprobación correcta sería sobre el índice, no sobre el valor:

    if (i == datos.length) {
    System.out.println("No hay ningún cero");
} else {
    System.out.println("Hay un cero en la posición " + i);
}

    Traza 05 · La búsqueda binaria

    Con el array ordenado {18, 21, 25, 30, 33, 36, 40, 45, 52, 60} buscando el 45:

    int[] edad = {18, 21, 25, 30, 33, 36, 40, 45, 52, 60};
int izq = 0;
int der = edad.length - 1;
boolean encontrado = false;

while (izq <= der && !encontrado) {
    int m = (izq + der) / 2;
    if (edad[m] == 45) {
        encontrado = true;
    } else if (edad[m] > 45) {
        der = m - 1;
    } else {
        izq = m + 1;
    }
}

System.out.println(encontrado + " " + (izq + 1));
    Solución 
    true 6
    Vuelta izq der m = (izq+der)/2 edad[m] Comparación Acción
    Inicio 0 9 — — — —
    1.ª 0 9 4 33 ¿45 = 33? No. ¿33 > 45? No izq = 5
    2.ª 5 9 7 45 ¿45 = 45? Sí encontrado = true

    El programa da una respuesta inútil

    Imprime izq + 1 = 5 + 1 = 6, pero el 45 está en el índice 7. El resultado es un número sin ningún sentido.

    La causa está en el diseño del programa, no en la búsqueda: un método que solo devuelve boolean pierde la posición en la que encontró el elemento.

    La versión que sí sirve

    Devuelve la posición, no un booleano:

    public static int buscarEdad(int[] edad, int objetivo) {
    int izq = 0;
    int der = edad.length - 1;

    while (izq <= der) {
        int m = (izq + der) / 2;
        if (edad[m] == objetivo) {
            return m;                    // Devolvemos la posición
        } else if (edad[m] > objetivo) {
            der = m - 1;
        } else {
            izq = m + 1;
        }
    }
    return -1;                           // No está
}

    Con este método, buscarEdad(edad, 45) devuelve 7, que es correcto.

    Cuántas comparaciones

    Con 10 elementos, solo 2 vueltas. Con búsqueda lineal habrían hecho falta hasta 8. Con 1000 elementos serían 10 vueltas frente a 1000.

    Traza 06 · La búsqueda binaria que no encuentra

    Mismo array, buscando ahora el 35 (no está):

    Solución
    Vuelta izq der m edad[m] ¿35 > edad[m]? Acción
    1.ª 0 9 4 33 ¿35 = 33? no. ¿33 > 35? no izq = 5
    2.ª 5 9 7 45 ¿35 = 45? no. ¿45 > 35? sí der = 6
    3.ª 5 6 5 36 ¿35 = 36? no. ¿36 > 35? sí der = 4
    — 5 4 — — izq <= der → 5 <= 4 es falso Sale

    encontrado sigue siendo false. El programa imprime false 6 (porque izq + 1 = 6), un valor sin sentido: por eso la búsqueda binaria debe devolver la posición, no un booleano.

    int[] v = {5, 2, 8, 1};

for (int i = 0; i < v.length - 1; i++) {
    int posMin = i;
    for (int j = i + 1; j < v.length; j++) {
        if (v[j] < v[posMin]) {
            posMin = j;
        }
    }
    int aux = v[posMin];
    v[posMin] = v[i];
    v[i] = aux;
}

System.out.println(Arrays.toString(v));
    Solución 
    [1, 2, 5, 8]
    i posMin j revisados v al terminar la vuelta
    Inicio — — [5, 2, 8, 1]
    0 0 → 3 1, 2, 3 [1, 2, 8, 5]
    1 1 2, 3 [1, 2, 8, 5] (sin cambio)
    2 2 → 3 3 [1, 2, 5, 8]

    Detalle de la vuelta i = 2: posMin empieza en 2, y v[2] es 8. Se revisa j = 3: v[3] = 5 < v[2] = 8 → posMin = 3. Luego se intercambian v[3] y v[2].

    Fíjate en el array tras cada vuelta

    • Tras i = 0: la posición 0 ya está definitivamente correcta.
    • Tras i = 1: las posiciones 0 y 1 son correctas.
    • Tras i = 2: las posiciones 0, 1 y 2 son correctas.
    • La posición 3 no se toca: es la última, y no hay nada a su derecha.

    Traza 08 · Un intercambio accidental

    1
2
3
4
5
6
7
    int[] v = {3, 1, 2};
int posMin = 0;
int aux = v[posMin];
v[posMin] = v[1];
v[1] = aux;

System.out.println(Arrays.toString(v));
    Solución 
    [1, 3, 2]
    Línea aux v
    Inicial — [3, 1, 2]
    int aux = v[0]; 3 [3, 1, 2]
    v[posMin] = v[1]; → v[0] = v[1] 3 [1, 1, 2] ⚠️
    v[1] = aux; 3 [1, 3, 2]

    El orden de estas tres líneas es crítico

    Si inviertieras las dos últimas:

    v[1] = aux;              // v[1] = 3  ← PERDIÓ el 1
v[posMin] = v[1];        // v[0] = 3  ← ya no hay un 1 que copiar

    El resultado sería [3, 3, 2]: el 1 se habría perdido. Por eso aux se guarda siempre antes de tocar nada.

    Es el mismo mecanismo del intercambio de la UD02, y funciona aquí porque la variable auxiliar copia el valor.

    Traza 09 · Arrays.fill y toString

    1
2
3
4
5
    int[] v = {1, 2, 3, 4};
System.out.println(Arrays.toString(v));
Arrays.fill(v, 0);
System.out.println(Arrays.toString(v));
System.out.println(v);
    Solución 
    [1, 2, 3, 4]
[0, 0, 0, 0]
[I@1b6d3586

    La tercera línea es la trampa

    System.out.println(v) no imprime el contenido: imprime el array como si fuera un objeto, y Java muestra su dirección de memoria ([I@1b6d3586).

    Para ver el contenido, siempre Arrays.toString(v). Esta es la razón principal por la que el criterio de evaluación b) menciona las librerías de clases.

    fill modifica el array original

    Arrays.fill(v, 0) cambia v para siempre. No hay forma de "deshacerlo". Por eso, si necesitas conservar el contenido, rellena un array nuevo.
