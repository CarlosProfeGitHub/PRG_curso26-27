    7. Problemas de ordenación y for-each

    7.1. Qué es un problema de ordenación

    Definición

    Un problema de ordenación consiste en colocar los elementos del array en un orden determinado: ascendente, descendente, alfabético…

    Los algoritmos se clasifican en dos familias:

    Tipo Ejemplos Cuándo usarlos
    Iterativos Burbuja, selección directa, inserción Cuando quieres ver cómo funciona el algoritmo
    Recursivos mergeSort, quickSort Cuando necesitas eficiencia (muchos datos)

    En la librería estándar ya existen todos

    Arrays.sort() implementa un algoritmo muy eficiente. En el trabajo real, usa la librería (como se explica en el §9.2). Pero en la unidad necesitas escribir el algoritmo a mano para entender cómo funciona.

    Ejemplos visuales de ordenación

    Visualgo muestra, paso a paso y con barras de colores, cómo funciona cada algoritmo con distintos tipos de entrada. Es la mejor forma de entender por qué la selección directa y la burbuja son lentas.

    7.2. Selección directa

    ¿En qué consiste?

    1. Recorre el array ascendentemente a partir de la posición 0.
    2. En cada posición i, localiza el menor de los elementos que quedan a su derecha.
    3. Coloca ese menor en la posición i intercambiándolo con lo que hubiera ahí.

    Con ello, el array queda ordenado hasta la posición i.

    public static void seleccionDirecta(int[] v) {

    for (int i = 0; i < v.length - 1; i++) {
        // Localizamos el elemento que tiene que ir en la posición i
        int posMin = i;

        // Buscamos el menor a la derecha
        for (int j = i + 1; j < v.length; j++) {
            if (v[j] < v[posMin]) {
                posMin = j;
            }
        }

        // Intercambiamos los elementos de las posiciones i y posMin
        int aux = v[posMin];
        v[posMin] = v[i];
        v[i] = aux;
    }
}

    Los tres bucles internos en uno

    Línea Qué hace
    for (int i = 0; i < v.length - 1; i++) Recorre las posiciones que se van a fijar
    int posMin = i; El mínimo empieza siendo el propio elemento de i
    for (int j = i + 1; ...) Busca si hay algo más pequeño a la derecha
    El intercambio Coloca el mínimo en su sitio

    Dos detalles que se olvidan

    1. El bucle externo va hasta length - 2, no hasta length - 1: cuando i llega a la última posición, no queda nada a su derecha y no hay nada que ordenar.
    2. El bucle interno empieza en i + 1: comparar el elemento consigo mismo es un trabajo inútil.

    Traza completa

    Con v = {5, 2, 8, 1, 9}:

    i posMin Elementos comparados (j) Valor mínimo Intercambio Array resultante
    Inicio — — — — 5 2 8 1 9
    0 0 → 3 1, 2, 3, 4 1 (en pos 3) v[0] ↔ v[3] 1 2 8 5 9
    1 1 2, 3, 4 2 (ya está en 1) No hace falta 1 2 8 5 9
    2 2 → 3 3, 4 5 (en pos 3) v[2] ↔ v[3] 1 2 5 8 9
    3 3 4 8 (ya está) No hace nada 1 2 5 8 9

    Fíjate en la línea 2 del array

    En la vuelta i = 0 el array ya queda ordenado hasta la posición 0. En la vuelta i = 1, hasta la posición 1. Al terminar, está ordenado entero. Esa es la garantía del algoritmo.

    El intercambio sin variable auxiliar

    Si los dos elementos están en posiciones distintas, el intercambio necesita una variable auxiliar. Si son la misma (posMin == i), el intercambio es un no-op inofensivo, pero funciona.

    El intercambio de "sin auxiliar" con v[i] += v[posMin]; v[posMin] -= v[i]; v[i] -= v[posMin]; solo es correcto si son la misma posición, y en caso contrario rompe el array. Usa siempre la variable auxiliar.

    7.3. Ordenación con Arrays.sort()

    Como se detalla en el §9.2:

    int[] v = {5, 2, 8, 1, 9};
Arrays.sort(v);

    No es una utopía

    Arrays.sort(v) modifica el array original: no devuelve nada (void). Si necesitas conservar el original, trabaja sobre una copia:

    int[] copia = v.clone();
Arrays.sort(copia);

    7.4. El bucle for-each

    Hasta ahora has recorrido arrays con un índice i que va de 0 a length - 1. El for-each (o for-in) permite recorrerlos sin índice.

    int[] array = {1, 2, 3, 4, 5, 6, 7, 8};

for (int elemento : array) {
    // mentalmente: "para cada entero elemento que
    // encontremos en el array"
    System.out.print(elemento + " ");
}
    Resultado 
    1 2 3 4 5 6 7 8

    El precio que pagas: no hay índice

    Con el for-each no tienes acceso a la posición. La variable elemento contiene el valor, no el índice.

    for (int i = 0; i < array.length; i++) {
    if (array[i] == 5) {
        System.out.println("Está en la posición " + i);   // ✅ Con el for clásico
    }
}

for (int elemento : array) {
    if (elemento == 5) {
        System.out.println("Está en la posición ?");     // ❌ No sabemos dónde está
    }
}

    Elige el bucle según lo que necesites

    Necesitas… Usa
    Solo el valor for-each
    La posición (i) for clásico
    Recorrer en sentido inverso for clásico
    Comparar con el elemento anterior for clásico

    for-each no sirve para recorrer al revés

    No hay forma de "ir hacia atrás" con un for-each. Para eso necesitas el for clásico empezando por length - 1.

    Otra limitación: no puedes cambiar el tamaño

    Con un for-each no puedes modificar la longitud del array (ni asignar un array nuevo a la variable del bucle):

    for (int e : array) {
    array = new int[10];    // ❌ No afecta al recorrido, y confunde
}

    Solo puedes modificar los valores de sus componentes.

    7.5. Comparativa de los dos bucles

    for clásico for-each
    Sintaxis for (int i = 0; i < a.length; i++) for (int e : a)
    Necesita .length Sí No
    Acceso al índice Sí No
    Sentido inverso Sí No
    Riesgo de salirte un elemento Sí (<= en vez de <) No
    Más seguro frente a errores ✅

    El for-each no se puede usar para buscar

    Como no da el índice, no sirve para nada que necesite la posición: búsquedas, indexes del elemento mayor, contar cuántas veces aparece algo en una posición concreta. Para eso, siempre for clásico.
