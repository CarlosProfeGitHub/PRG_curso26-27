    14. Errores frecuentes y cómo solucionarlos

    14.1. Errores de compilación

    # Mensaje de error Causa Solución
    1 int[] a; a = new int; Falta el tamaño: new int no es válido. Escribe new int[5].
    2 cannot find symbol: method length() Escribiste length() con paréntesis. length es un atributo, sin paréntesis.
    3 no suitable method found for … al asignar length es de solo lectura. No se puede cambiar el tamaño de un array.
    4 incompatible types: int cannot be converted to int[] a = 25; en lugar de a[0] = 25;. Pon los corchetes con la posición.
    5 variable a might not have been initialized Usas el array antes de crearlo con new. Declara y crea en la misma línea, o sepáralas en orden.
    6 cannot find symbol: class Arrays Falta el import java.util.Arrays;. Añádelo al principio del archivo.
    7 bad operand types for binary operator '+' Intentas concatenar el array con un String usando +. Usa Arrays.toString(a).
    8 variable i is already defined Dos locales del mismo método con el mismo nombre. Renombra una de las dos.
    9 array required, but int found Quieres indexar (a[i]) algo que no es un array. Revisa el tipo de la variable.
    10 incompatible types: int[][] … new int[3] new int[3] crea un array 1D, no una matriz. Escribe new int[3][3].

    14.2. ArrayIndexOutOfBoundsException

    Es el error más frecuente de la unidad. Se produce al acceder a una posición que no existe.

    Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException: Index 31 out of bounds for length 31
    Causa Ejemplo Solución
    El + 1 de más for (int i = 0; i <= v.length; i++) El último índice es length - 1: usa <
    Empezar por 1 for (int i = 1; i <= v.length; i++) El array empieza en 0
    Acceder después del bucle while (i < len && v[i] != 0) i++; y luego v[i] Comprueba i == len antes de acceder
    Una matriz vacía new int[3][] y luego c[0][0] c[0] es un int, no un array
    Filas desiguales Recorrer con m[0].length como si todas tuvieran lo mismo Usa m[f].length en cada fila

    El for con <= es el más común

    for (int i = 0; i <= v.length; i++)     // ❌ Se sale al final
for (int i = 0; i <  v.length; i++)     // ✅ Correcto

    El truco para recordarlo

    < significa "menos que la cantidad de índices", y hay exactamente length índices válidos. El último es length - 1, que es menos que length.

    14.3. Errores de lógica (compila pero da un resultado incorrecto)

    # Síntoma Causa habitual Cómo diagnosticarlo
    1 El máximo siempre vale 0 o un número fijo Inicializaste con 0 en vez de datos[0]. Prueba con un array todo negativo.
    2 El mínimo siempre vale 0 Ídem, con datos[0]. Prueba con un array todo positivo.
    3 El array sale con un 0 al final Te sobró una posición al calcular el tamaño. Revisa el cálculo de cuantos.
    4 La búsqueda siempre dice que no está Condición invertida o accessing fuera de rango. Imprime i en cada vuelta.
    5 La búsqueda binaria falla a veces El array no está ordenado. Ordena antes de buscar.
    6 La suma sale un número entero División entera: suma / v.length con int. (double) suma / v.length.
    7 La tabla sale con huecos Comprobaste la condición al revés. if (indice < datos.length).
    8 El array se "corrompe" Un intercambio mal hecho, o fill/sort sobre el original. Copia antes de modificar.
    9 Falla solo con arrays pequeños Bucle que empieza en 1, o datos[0] en un array vacío. Prueba con length = 1.
    10 Imprime [I@1b6d3586 println(array) en vez de Arrays.toString(). Usa Arrays.toString(v).

    Los tres errores que más puntos cuestan

    1. Inicializar el máximo con 0.

    double max = 0;              // ❌ Falla con {−5, −2, −9}
double max = datos[0];       // ✅ Siempre correcto

    2. Comprobar si se acabó el array accediendo al array.

    if (datos[i] == 0) { ... }          // ❌ Si i == length, revienta
if (i == datos.length) { ... }      // ✅ Compara índices

    3. Recorrer con <=.

    Es el error que más veces se cuela en un examen porque el programa funciona con arrays grandes: solo falla en el último elemento. Si pruebas con 10 elementos y da error, sabrás que hay algo mal antes de entregarlo.

    Herramientas de depuración

    • Imprime el array con Arrays.toString() antes y después de cada operación que lo modifique. Es la forma más rápida de ver qué ha cambiado.
    • for (int i = 0; i < v.length; i++) con un System.out.println(i + " -> " + v[i]); dentro te muestra exactamente qué celda estás mirando en cada vuelta.
    • Punto de inspección: en Eclipse, Pon el cursor sobre v.length y mira el valor en la vista Variables.
