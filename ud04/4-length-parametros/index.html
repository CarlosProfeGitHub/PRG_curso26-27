    4. El atributo length y los arrays como parámetros

    4.1. El atributo length

    Todas las variables de tipo array tienen un atributo length que devuelve el número de componentes. Se usa posponiendo .length al nombre de la variable.

    1
2
3
    double[] estatura = new double[25];

System.out.println(estatura.length);   // Imprime 25

    length es de tipo int, no de tipo String

    Es un atributo, no un método. Fíjate en que no lleva paréntesis: .length y no .length().

    Por qué length es tan importante

    Permite escribir bucles que se adaptan solos al tamaño del array:

    for (int i = 0; i < datos.length; i++) { ... }

    Este bucle funciona igual con 3 elementos que con 3000. Si en su lugar escribieras i < 10, el programa se rompería en cuanto el array tuviera menos de 10 componentes.

    El clásico error del = en lugar del <

    for (int i = 0; i = datos.length; i++) { ... }   // ❌ i = length es una ASIGNACIÓN

    Esto no da error de compilación: asigna a i el valor de length y comprueba si es distinto de cero. Como length nunca es 0, el bucle se ejecuta para siempre (hasta desbordar el índice). Es un bucle infinito disfrazado.

    4.2. Arrays como parámetros: el paso por referencia

    Hasta ahora has visto que los parámetros de tipos simples se pasan por valor. Los arrays son otra cosa.

    Los arrays NO son tipos primitivos

    En Java, los arrays no son variables de tipo primitivo. Como cualquier otro objeto, se pasan siempre por referencia.

    En el paso por referencia, lo que se pasa al método no es el contenido, sino la dirección de memoria del array. El parámetro formal actúa como una referencia al parámetro real, y la llamada no crea una variable nueva.

    public class PasoPorReferencia {

    public static void main(String[] args) {
        int p = 1;
        int[] v = {1, 1, 1};

        metodo(v, p);                  // Pasar un array como parámetro

        System.out.println(p);         // Muestra 1: no ha cambiado
        System.out.println(v[0]);      // Muestra 2: sí ha cambiado
    }

    public static void metodo(int x[], int y) {
        x[0]++;                        // Modifica el array original
        y++;                           // Solo modifica la copia
    }
}
    Resultado 
    1
2
    Parámetro Tipo Qué recibe ¿Se nota el cambio fuera?
    v → x int[] (referencia) La dirección del array Sí
    p → y int (valor) Una copia del 1 No

    La analogía

    • Un int es una caja con un número dentro. Al pasarlo, das la caja y te quedas sin ella: el método trabaja con una copia y tú no te enteras.
    • Un array es la caja que contiene las direcciones de los datos. Al pasarlo, das una copia de la dirección: el método sigue señalando al mismo array. Si modifica lo que hay dentro, tú lo ves.

    Cómo se declara un array como parámetro

    En la llada, se usa el nombre de la variable tal cual. En la cabecera del método, hay que usar los corchetes:

    // ---------- EN LA LLADA ----------
double media = calcularMedia(lluvia);

// ---------- EN LA CABECERA DEL MÉTODO ----------
public static double calcularMedia(double datos[]) {
    double suma = 0;
    for (int i = 0; i < datos.length; i++) {
        suma += datos[i];
    }
    return suma / datos.length;
}

    Por qué esto es tan útil

    Un método que recibe double[] sirve para cualquier array de doubles: el de enero, el de febrero o el de cualquier mes. Es la modularidad de la UD03 aplicada a las estructuras de datos.

    Y como el método ve las modificaciones del array, también puede usarlo para rellenarlo: es el mecanismo de las funciones tipo rellenar.

    El riesgo del paso por referencia

    Como el método ve el array original, cualquier cambio se conserva. Eso es potente, pero también peligroso:

    public static void ponerOcho(int[] numeros) {
    numeros[0] = 8;          // ❗ Modifica el array del llamante
}

    Si no quieres que el método toque el array del llamante, pásale una copia:

    int[] copia = new int[original.length];
System.arraycopy(original, 0, copia, 0, original.length);

    4.3. Los arrays con String[] args del main

    El programa puede recibir argumentos desde la línea de comandos

    El método main recibe un parámetro especial, String[] args, que es un array de cadenas. Cada argumento que el usuario escribe al ejecutar el programa se guarda en una posición.

    java EsNavidad 25 12
    args Valor
    args[0] "25"
    args[1] "12"
    args.length 2

    El uso de args.length permite comprobar que el programa se ha llamado correctamente:

    public class EsNavidad {
    public static void main(String[] args) {
        if (args.length != 2) {
            System.out.println("ERROR:");
            System.out.println("Llame al programa de la siguiente forma:");
            System.out.println("java EsNavidad dia mes");
        } else {
            // args[0] es el día
            // args[1] es el mes
            int dia = Integer.parseInt(args[0]);
            int mes = Integer.parseInt(args[1]);

            if (dia == 25 && mes == 12) {
                System.out.println("¡ES NAVIDAD!");
            } else {
                System.out.println("No es Navidad :(");
            }
        }
    }
}
    Ejecuciones 
    $ java EsNavidad 25 12
¡ES NAVIDAD!

$ java EsNavidad 24 12
No es Navidad :(

$ java EsNavidad
ERROR:
Llame al programa de la siguiente forma:
java EsNavidad dia mes

    Integer.parseInt() es imprescindible

    args[0] es el texto "25", no el número 25. Para compararlo con un entero hay que convertirlo:

    int dia = Integer.parseInt(args[0]);

    La comparación que no funciona

    if (args[0] == 25) { ... }        // ❌ ERROR de compilación: String vs int
if (args[0].equals("25")) { ... } // ✅ Compara texto, no número

    Y ojo: "25".equals("25") funciona, pero args[0] == args[1] compara direcciones, no contenidos. Para comparar cadenas usa siempre .equals().

    4.4. Cómo declarar el array en el main

    Cuatro formas, todas válidas

    int[] a = new int[5];              // Declaración + creación
int b[] = new int[5];              // Lo mismo, corchetes al final
int[] c = {1, 2, 3};               // Con valores iniciales
int[] d;                           // Solo declaración (aún sin crear)
d = new int[5];                    // Creación por separado

    En el último caso, d no existe hasta la línea de creación: usar d antes daría el error variable d might not have been initialized.
