    2. El problema de organizar los datos

    Hasta ahora has resuelto el mundo con int a, int b, int c… una variable por dato. Eso funciona para dos o tres valores. En cuanto necesitas treinta, el programa se rompe.

    La pregunta de esta unidad

    ¿Cómo guardo treinta y un valores en una sola variable y los trato como si fueran uno?

    2.1. El problema de la pluviosidad

    Supongamos que hay que leer la pluviosidad de cada uno de los 31 días de un mes y después mostrar la media del mes y en cuántos días las lluvias superaron esa media.

    Con las herramientas que tienes hasta ahora, la única forma de guardar 31 números sería esto:

    1
2
3
4
    double dia1, dia2, dia3, dia4, dia5, dia6, dia7, dia8;
double dia9, dia10, dia11, dia12, dia13, dia14, dia15, dia16;
double dia17, dia18, dia19, dia20, dia21, dia22, dia23, dia24;
double dia25, dia26, dia27, dia28, dia29, dia30, dia31;

    Y para sacar la media, un programa de pesadilla:

    1
2
3
4
    double media = (dia1 + dia2 + dia3 + dia4 + dia5 + dia6 + dia7 + dia8
              + dia9 + dia10 + dia11 + dia12 + dia13 + dia14 + dia15 + dia16
              + dia17 + dia18 + dia19 + dia20 + dia21 + dia22 + dia23 + dia24
              + dia25 + dia26 + dia27 + dia28 + dia29 + dia30 + dia31) / 31;

    Este programa es un desastre, y hay que saber por qué

    • No escala: con 32 días habría que reescribirlo todo.
    • No se puede recorrer: no hay forma de decir "suma todas las variables que empiezan por dia".
    • Es imposible de reutilizar: si mañana necesito la pluviosidad de otro mes, tengo que copiar y pegar las 31 líneas.
    • Falla al momento de leer: hay que escribir 31 bloques de System.out.print("Día N: ").

    El problema de fondo no es que falte sintaxis: es que no existe una estructura que represente "muchos datos del mismo tipo".

    2.2. La solución: el array

    Un array es una colección de elementos del mismo tipo que comparten un nombre común. Con él, el problema anterior se convierte en:

    1
    double[] lluvia = new double[31];

    Y la media:

    1
2
3
4
5
    double suma = 0;
for (int i = 0; i < lluvia.length; i++) {
    suma += lluvia[i];         // 31 iteraciones, escritas UNA vez
}
double media = suma / 31;

    Qué ha cambiado realmente

    Antes Después
    31 variables 1 variable
    4 líneas para sumar 4 líneas, pero valen para 31 datos y para 3000
    Cada dato nuevo obliga a tocar el código El bucle se adapta solo
    Imposible de reutilizar Es una función que recibe double[]

    Un array no es un número

    lluvia no vale 31. Vale "una lista de 31 cosas". Si escribes System.out.println(lluvia) obtendrás algo como [D@1b6d3586, que es la dirección de memoria del array. Para ver su contenido hay que recorrerlo o usar Arrays.toString(), como se explica en el §9.2.

    2.3. Qué clasificación tienen los problemas con arrays

    La mayoría de los problemas con arrays se pueden clasificar en tres grupos. Los vas a ver siempre:

    Grupo Pregunta que responde Ejemplo
    Recorrido ¿Hay que mirar todos los elementos? Sumar, contar, hallar el máximo
    Búsqueda ¿Hay algún elemento que cumpla una condición? ¿Quién tiene un 7? ¿Hay algún negativo?
    Ordenación ¿Hay que poner los elementos en orden? De mayor a menor

    Por qué importa la clasificación

    Porque la eficiencia depende del grupo. Una búsqueda sobre un array ordenado se puede resolver en log₂(n) pasos (búsqueda binaria), pero sobre uno no ordenado hay que revisarlo entero sí o sí. Elegir el algoritmo adecuado es la diferencia entre milisegundos y horas.

    Los algoritmos de búsqueda, ordenación y recorrido son, además, los mismos que se usan con listas, ficheros o cualquier otra colección de datos.

    2.4. Qué vas a ser capaz de hacer al terminar

    • Declarar y crear arrays de cualquier tipo, con el tamaño que quieras.
    • Acceder y modificar cualquier elemento por su índice.
    • Recorrer un array completo en orden ascendente y descendente.
    • Buscar un elemento de tres maneras distintas y saber cuál conviene.
    • Ordenar un array con un algoritmo propio.
    • Declarar e inicializar matrices y arrays multidimensionales.
    • Usar la librería java.util.Arrays para las tareas habituales.

    Puente con las unidades anteriores y siguientes

    • La estructura de control for de la UD02 es la herramienta clave: todo recorrido es un for con una condición sobre .length.
    • La modularidad de la UD03 es lo que hace útil el paso de arrays por parámetro: un método que recibe double[] es reutilizable con cualquier mes.
    • Las colecciones de la UD05 resuelven el problema que el array deja abierto: cambiar el tamaño.
