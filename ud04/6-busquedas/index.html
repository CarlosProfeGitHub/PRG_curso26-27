    6. Problemas de búsqueda

    6.1. Qué es un problema de búsqueda

    Definición

    Se denominan problemas de búsqueda aquellos que, de alguna manera, implican determinar si existe algún elemento del array que cumpla una propiedad dada.

    La diferencia con el recorrido es clave:

    Recorrido Búsqueda
    ¿Necesita tratar todos los elementos? Sí No necesariamente
    ¿Cuándo termina? Al acabar el array Al encontrar el elemento

    El elemento puede estar en tres sitios

    1. Al principio: la búsqueda termina en la primera vuelta.
    2. En medio: hay que avanzar un poco.
    3. En ninguna parte: hay que recorrerlo entero y devolver que no está.

    Un buen algoritmo de búsqueda es el que detecta rápido el caso 1 y no falla en el caso 3.

    /**
 * Devuelve el subíndice del primer día sin lluvia.
 *
 * @param lluvia array con la pluviosidad de cada día
 * @return la posición del primer día sin lluvia, o -1 si no hay ninguno
 */
public static int primerDiaSinLluvia1(double[] lluvia) {
    int i = 0;
    boolean encontrado = false;

    while (i < lluvia.length && !encontrado) {
        if (lluvia[i] == 0) {
            encontrado = true;
        } else {
            i++;
        }
    }

    if (encontrado) {
        return i;
    } else {
        return -1;
    }
}

    La doble condición del while

    while (i < lluvia.length && !encontrado)

    Las dos partes son necesarias y responden a dos preguntas distintas:

    Condición Pregunta
    i < lluvia.length ¿He llegado al final del array?
    !encontrado ¿Ya encontré lo que buscaba?

    El orden importa

    Si inviertieras las condiciones, lluvia[i] se evaluaría con i == length justo en la última vuelta, y el programa daría ArrayIndexOutOfBoundsException.

    public static int primerDiaSinLluvia2(double[] lluvia) {
    int i = 0;

    while (i < lluvia.length && lluvia[i] != 0) {
        i++;
    }

    // Salimos por dos motivos distintos: hay que averiguarlo
    if (i == lluvia.length) {
        return -1;                  // Se acabó el array sin encontrarlo
    } else {
        return i;                   // Lo encontramos en la posición i
    }
}

    Cuando el bucle termina porque i alcanzó lluvia.length, esa posición no existe en el array. Al acceder a lluvia[i] se lanza:

    ArrayIndexOutOfBoundsException: Index 31 out of bounds for length 31

    La comparación segura compara índices, no valores

    Pregunta Comparación segura
    ¿He llegado al final? i == lluvia.length
    ¿Lo he encontrado? i < lluvia.length

    Nunca accedas al array para comprobar si has llegado al final: es justo lo que no se puede hacer.

    Versión Legibilidad Recomendación
    Con boolean ⭐⭐⭐ Muy clara La más recomendable para aprender y para examinations

    Con for vacío ⭐ Poco intuitiva Evítala si puedes

    La versión con boolean se lee como la frase que describe el problema. Usa esa mientras estés aprendiendo.

    public static int ultimoDiaSinLluvia(double[] lluvia) {
    int i = lluvia.length - 1;
    boolean encontrado = false;

    while (i >= 0 && !encontrado) {
        if (lluvia[i] == 0) {
            encontrado = true;
        } else {
            i--;
        }
    }

    if (encontrado) {
        return i;
    } else {
        return -1;
    }
}

    Cambia el punto de partida, no la estructura

    Ascendente Descendente
    Inicio int i = 0; int i = lluvia.length - 1;
    Condición i < lluvia.length i >= 0
    Paso i++ i--
    Devuelve El primer que cumple El último que cumple

    El resto del método es idéntico. Eso es la prueba de que has entendido el esquema.

    6.6. Búsqueda binaria: cuando el array está ordenado

    El problema de adivinar un número

    Supón que hay que adivinar un número secreto entre 0 y 99. La estrategia "ingenua" es probarlos uno a uno: 0, 1, 2…

    • Mejor caso: sale 0 → 1 intento.
    • Peor caso: sale 99 → 100 intentos.

    La estrategia inteligente empieza por el medio: 50. Si es mayor, pruebas entre 51 y 99; si es menor, entre 0 y 49. Y así hasta adivinarlo.

    En el caso de 100 valores, esto garantiza adivinarlo en 7 intentos como máximo, en lugar de 100. El número de intentos es siempre como máximo log₂(N).

    Ese algoritmo se llama búsqueda binaria o dicotómica.

    ¿Por qué funciona?

    Solo si el array está ordenado. Si el elemento central es mayor que el buscado, sabemos que todos los elementos de la mitad derecha son también mayores. Eso nos permite descartar media mitad de golpe.

    Situación Qué hacer
    El elemento central es el buscado Terminar: hemos terminado
    El central es mayor que el buscado Seguir en la mitad izquierda
    El central es menor que el buscado Seguir en la mitad derecha

    /**
 * Indica si alguna persona del grupo tiene 36 años.
 * El array de edades debe estar ORDENADO de menor a mayor.
 *
 * @param edad array de edades ordenado
 * @return true si hay alguien con 36 años, false en caso contrario
 */
public static boolean hayAlguienDe36(int[] edad) {
    // Las variables izq y der marcan el fragmento del array en el que
    // buscamos. Inicialmente buscamos en todo el array.
    int izq = 0;
    int der = edad.length - 1;
    boolean encontrado = false;

    while (izq <= der && !encontrado) {
        // Calculamos la posición central del fragmento
        int m = (izq + der) / 2;

        if (edad[m] == 36) {
            encontrado = true;
        } else if (edad[m] > 36) {
            // El central tiene más de 36: seguimos en la mitad izquierda,
            // entre las posiciones izq y m-1
            der = m - 1;
        } else {
            // El central tiene menos de 36: seguimos en la mitad derecha,
            // entre las posiciones m+1 y der
            izq = m + 1;
        }
    }

    return encontrado;
}

    Las dos condiciones de salida son obligatorias

    while (izq <= der && !encontrado)
    Condición Cuándo se cumple
    izq <= der El fragmento se ha quedado vacío: no queda nada que buscar
    !encontrado Hemos encontrado el elemento

    Si quitas izq <= der, el bucle se ejecuta para siempre. Fíjate en cómo der = m - 1 y izq = m + 1 van acortando el fragmento en cada vuelta: en algún momento izq supera a der y se detiene.

    La traza completa

    Con el array ordenado {18, 21, 25, 30, 33, 36, 40, 45, 52, 60}, buscando el 36:

    Vuelta izq der m = (izq+der)/2 edad[m] Decisión
    Inicio 0 9 — — Buscamos en todo el array
    1.ª 0 9 4 33 ¿36 > 33? → derecha
    2.ª 5 9 7 45 ¿36 < 45? → izquierda
    3.ª 5 6 5 36 ¡Encontrado!

    Un solo paso descarta media mitad

    Fíjate en la primera vuelta: de 10 elementos pasamos a buscar entre los índices 5 y 9, es decir 5 elementos. De 1000 pasaríamos a 500. Ese es el poder de la búsqueda binaria.

    Comparación de eficiencia

    Elementos Búsqueda lineal Búsqueda binaria (log₂ N)
    10 10 intentos 4
    100 100 intentos 7
    1 000 1 000 intentos 10
    1 000 000 1 000 000 intentos 20

    La contrapartida: el array DEBE estar ordenado

    La búsqueda binaria da resultados incorrectos si el array no está ordenado, porque asume que todo lo que está a la derecha del centro es mayor.

    Prueba del clásico error

    Con el array desordenado {5, 80, 3, 12, 45, 22, 9} buscando el 22:

    Vuelta izq der m array[m] Decisión
    1.ª 0 6 3 12 ¿22 > 12? → derecha: izq = 4
    2.ª 4 6 5 22 ¡Encontrado!

    En este caso sí funciona por casualidad. Pero con {80, 5, 45, 3, 22} buscando el 22, la primera vuelta mira 45, decide "izquierda" y descarta el 22 que estaba en la posición 4. El método devolvería false mintiendo: el 22 está ahí.

    Antes de usar búsqueda binaria, responde

    1. ¿El array está ordenado?
    2. ¿Por cuál de los dos lados?

    Si no puedes contestar las dos, usa la búsqueda lineal.

    La versión recursiva

    Como viste en la UD03 · §9.2, la búsqueda binaria se puede escribir recursivamente, y resulta bastante más natural: cada llamada busca en la mitad del array.

    ¿Cuál usar?

    Iterativa (while) Recursiva
    Consumo de memoria Solo 3 variables Una llamada por nivel
    Legibilidad Algo más técnica Muy natural
    Riesgo Bajo StackOverflowError si el caso base falla

    Para los ejercicios de la unidad usa la iterativa. Menciona la recursiva si el enunciado la pide.
