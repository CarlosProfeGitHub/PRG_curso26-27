    13. Errores frecuentes y cómo solucionarlos

    13.1. Errores de compilación

    # Mensaje de error Causa Solución
    1 incompatible types: int cannot be converted to Integer Intentas añadir un primitivo a una colección de objetos. Usa Integer o confía en el autoboxing.
    2 cannot find symbol: class ArrayList Falta el import java.util.ArrayList;. Añádelo al principio del archivo.
    3 cannot find symbol: method size() Escribiste length en una colección. Las colecciones usan .size(), no .length.
    4 no suitable method found for add(int) La lista es de String y pasas un int. Pasa un String o cambia el tipo genérico.
    5 unchecked or unsafe operations Usas colecciones sin tipo genérico (raw types). Declara el tipo: List<String> lista = new ArrayList<>();.
    6 variable lista might not have been initialized Usas la lista antes de crearla con new. Declara y crea en la misma línea.
    7 cannot find symbol: method get(int) Llamas a get() sobre un Set o Map. Set no tiene acceso por índice. Usa un List.
    8 incompatible types: Object cannot be converted to String No usaste genéricos al declarar la lista. Añade <String> a la declaración.

    13.2. Excepciones en tiempo de ejecución

    Excepción Causa Solución
    NullPointerException Llamas a un método sobre una lista que es null. Crea la lista con new antes de usarla.
    IndexOutOfBoundsException Accedes a una posición que no existe en la lista (get(10) en una lista de 3). Comprueba indice < lista.size().
    ConcurrentModificationException Modificas la colección mientras la recorres con for-each. Usa Iterator y it.remove(), o removeIf.
    ClassCastException Intentas convertir un objeto a un tipo incompatible. Revisa los tipos genéricos y los casts.
    UnsupportedOperationException Llamas a add() o remove() sobre una lista inmutable (List.of(...)). Crea una copia mutable: new ArrayList<>(lista).
    NoSuchElementException Llamas a next() o poll() cuando no quedan elementos. Comprueba hasNext() o isEmpty() antes.
    EmptyStackException Llamas a pop() sobre una pila vacía. Comprueba isEmpty() antes de desapilar.

    El for-each con remove es el más común

    for (String s : lista) {
    if (s.equals("X")) lista.remove(s); // ❌ ConcurrentModificationException
}
    La solución es usar un Iterator: 
    Iterator<String> it = lista.iterator();
while (it.hasNext()) {
    if (it.next().equals("X")) it.remove(); // ✅
}

    13.3. Errores de lógica (compila pero da un resultado incorrecto)

    # Síntoma Causa habitual Cómo diagnosticarlo
    1 El conjunto no elimina duplicados Los objetos no tienen equals() y hashCode() bien implementados. Prueba con String o Integer primero.
    2 El TreeSet lanza ClassCastException Los objetos no implementan Comparable. Implementa Comparable o pasa un Comparator.
    3 El mapa sobrescribe valores sin avisar Usas put() con una clave que ya existía. Comprueba containsKey() antes de insertar.
    4 El recorrido del mapa no sale en orden Usas HashMap, que no garantiza orden. Usa TreeMap o LinkedHashMap.
    5 remove() no elimina el elemento En un List<Integer>, remove(2) elimina por índice, no por valor. Usa remove(Integer.valueOf(2)).
    6 La lista no crece Usas List.of() o Arrays.asList(), que son inmutables. Crea una copia con new ArrayList<>(lista).
    7 El iterador se "salta" elementos Llamas a next() dos veces en la misma vuelta. Guarda el resultado en una variable.
    8 poll() devuelve null inesperadamente La cola estaba vacía. Comprueba isEmpty() antes de extraer.

    Los tres errores que más puntos cuestan

    1. remove(int) vs remove(Object) en listas de enteros. 

    List<Integer> lista = new ArrayList<>(List.of(1, 2, 3));
lista.remove(2);            // ❌ Elimina el elemento en la posición 2 (el 3)
lista.remove(Integer.valueOf(2)); // ✅ Elimina el valor 2

    2. Modificar la colección durante el recorrido. Siempre usa Iterator o removeIf.

    3. Asumir que HashMap está ordenado. Si necesitas orden, usa TreeMap o LinkedHashMap.

    Herramientas de depuración

    • Imprime la colección con System.out.println(coleccion) antes y después de cada operación.
    • System.out.println(coleccion.size()) te dice cuántos elementos hay.
    • System.out.println(coleccion.getClass().getSimpleName()) te dice qué implementación estás usando realmente.
