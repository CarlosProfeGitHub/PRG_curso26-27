    3. Estructuras de selección

    La estructura de selección evalúa una expresión lógica y, según su resultado (true o false), ejecuta una secuencia de instrucciones u otra. Ese true/false lo proporcionan los operadores relacionales y lógicos que ya conoces del §6 de la UD01.

    La idea en una frase

    Si se cumple esta condición, haz esto; si no, haz lo otro.

    3.1. if simple

    Es la forma más básica: una condición y un bloque.

    if (expresión-lógica) {
    sentencia1;
    sentencia2;
}

    Si la expresión es true, se ejecuta el bloque. Si es false, el programa salta directamente a la instrucción siguiente al if.

    int edad = 22;

if (edad > 18) {
    System.out.println(edad + " es mayor de edad");
}

    22 es mayor de edad

    ¿Y si quiero hacer algo cuando NO se cumple?

    Entonces necesito la variante de doble alternativa. La cláusula else es opcional, pero se recomienda usarla siempre que haya que hacer algo en el caso contrario.

    3.2. if-else: doble alternativa

    if (expresión-lógica) {
    sentencias_1;      // si la condición es cierta
} else {
    sentencias_2;      // si la condición es falsa
}

    Solo una de las dos ramas se ejecuta, nunca las dos. Esta es la garantía del if-else: los dos bloques son excluyentes.

    3.3. else if: selección múltiple encadenada

    Cuando hay más de dos alternativas, encadenar if-else anidados se vuelve ilegible. La forma correcta es else if:

    if (condicion1) {
    sentencias1;
} else if (condicion2) {
    sentencias2;
} else if (condicion3) {
    sentencias3;
} else {
    sentencias_defecto;
}

    int temperatura = 3;
boolean nevando = true;

if (temperatura > 25) {
    System.out.println("A la playa!!!");
} else if (temperatura > 15) {
    System.out.println("A la montaña!!!");
} else if (temperatura < 5 && nevando) {
    System.out.println("A esquiar!!!");
} else {
    System.out.println("A descansar... zZz");
}

    A esquiar!!!

    El orden de las condiciones importa

    Java evalúa las condiciones de arriba abajo y se detiene en la primera que sea cierta. Por eso temperatura > 25 debe ir antes que temperatura > 15: si inviertieras el orden, los 20 grados entrarían por la primera rama y dirían "playa".

    El bug clásico de los intervalos

    if (nota >= 5 && nota < 7) {
    System.out.println("Bien");
}
if (nota >= 7 && nota < 9) {
    System.out.println("Notable");
}

    Esto no es una cadena: son dos if independientes, no un else if. Si la nota es 7, el primer if es falso y el segundo verdadero: funciona. Pero si la nota es 8 y el segundo if no estuviera, no imprimiría nada. Con else if el programa garantiza que una nota válida siempre cae en alguna rama.

    3.4. Anidamiento y el else suspendido

    Se pueden anidar condicionales: un if dentro del bloque de otro if. Funciona, pero hay que tener mucho cuidado con el else.

    Regla del else (el dangling else)

    Un else se asocia siempre al if inmediatamente anterior y más cercano que todavía no tenga un else. Esto se llama else suspendido (dangling else) y es la causa del error de lógica más desconcertante que existe.

    Mira este código. ¿Qué esperas que imprima con x = 20?

    int x = 20;
System.out.println("Comenzamos");

if (x >= 20)
    if (x > 50)
        System.out.println("Muy grande");
    else {
        if (x % 2 != 0)
            System.out.println("Impar");
    }
else if (x <= 20)
    System.out.println("Pequeño");

System.out.println("Terminamos");
    Solución (imprime esto) 
    Comenzamos
Terminamos

    No imprime "Pequeño", y esa es la sorpresa. Observa la sangría: el autor pretendía que el else if (x <= 20) fuera el else del if (x >= 20). Pero como el if (x >= 20) no tiene llaves, Java lo lee así:

    if (x >= 20) {            // El if exterior NO tiene else propio...
    if (x > 50) { ... } else { ... }   // ...el else se adosa a ESTE if interior
}
else if (x <= 20) { ... }              // ¿Y este else a qué if se adosa?

    Como el if (x > 50) interior ya se quedó con el else, el else if exterior se queda huérfano: en realidad se ha convertido en el else de otro if, y el compilador de hecho reorganiza el código para que compile. El resultado es que x >= 20 es cierto, se entra al bloque, x > 50 es falso, se comprueba x % 2 != 0 → 20 % 2 = 0 → falso, y no se imprime nada.

    La solución: llaves siempre

    Si escribes el código como querías que fuera, con llaves, el programa se comporta como esperas:

    if (x >= 20) {
    if (x > 50) {
        System.out.println("Muy grande");
    } else if (x % 2 != 0) {
        System.out.println("Impar");
    }
} else if (x <= 20) {
    System.out.println("Pequeño");
}

    Cuando anidas, indenta siempre

    La sangría es la única herramienta que tiene el lector para saber a qué if pertenece cada else. Si la sangría dice una cosa y las llaves dicen otra, el compilador gana y el humano se equivoca.

    public class CalificacionExamen {

    /*
     * Calcula la nota de un examen tipo test y su calificación.
     * Cada error anula media respuesta correcta.
     */

    public static void main(String[] args) {

        // ---------- Declaración e inicialización ----------
        int numAciertos = 17;
        int numErrores = 3;
        int numPreguntas = 20;
        String calificacion = "";

        // ---------- Procesamiento ----------
        // Restamos medio punto por cada error antes de escalar
        int nota = ((numAciertos - (numErrores / 2)) * 10) / numPreguntas;

        // ---------- Selección ----------
        if (nota < 5) {
            calificacion = "INSUFICIENTE";
        } else if (nota < 6) {
            calificacion = "SUFICIENTE";
        } else if (nota < 7) {
            calificacion = "BIEN";
        } else if (nota < 9) {
            calificacion = "NOTABLE";
        } else {
            calificacion = "SOBRESALIENTE";
        }

        // ---------- Salida ----------
        System.out.println("La nota obtenida es: " + nota);
        System.out.println("La calificación obtenida es: " + calificacion);
    }
}
    Resultado 
    La nota obtenida es: 8
La calificación obtenida es: NOTABLE

    Traza del cálculo: numErrores / 2 → 3 / 2 = 1 (división entera, ya lo estudiaste en UD01). Luego 17 - 1 = 16. Luego 16 * 10 = 160. Luego 160 / 20 = 8.

    Fíjate en la simplificación

    Los intervalos están escritos como nota < 6 en lugar de nota >= 5 && nota < 6. Ambas formas son correctas, pero la primera solo es válida porque cada condición se evalúa únicamente si todas las anteriores han resultado falsas. Es el else if quien te ahorra la mitad de las condiciones.
