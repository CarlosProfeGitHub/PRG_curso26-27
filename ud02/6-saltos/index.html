    6. Sentencias de salto

    Las sentencias de salto alteran el flujo normal de ejecución. En lugar de continuar con la siguiente instrucción, cambian el punto al que el control pasa.

    Uso responsable

    En general se desaconseja el uso de sentencias de salto incondicional: dificultan la lectura y el mantenimiento del código. Pero hay casos donde son necesarias (por ejemplo, salir de varios bucles anidados) y casos donde son la solución más limpia (por ejemplo, validar la entrada de un usuario). Por eso debes reconocerlas, aunque no las uses a diario.

    6.1. break: terminar una estructura

    break abandona inmediatamente el bucle o el switch donde se encuentra.

    1
2
3
4
5
6
    for (int i = 0; i < 10; i++) {
    if (i == 6) {
        break;
    }
    System.out.println("i: " + i);
}
    Resultado 
    i: 0
i: 1
i: 2
i: 3
i: 4
i: 5

    El bucle esté diseñado para 10 iteraciones, pero en i == 6 el break lo interrumpe. En cuanto se ejecuta, el programa salta a la instrucción siguiente al bucle.

    break solo afecta al bucle más interno

    En un bucle anidado, break solo termina el interno. El externo sigue su curso:

    1
2
3
4
5
6
7
8
    for (int i = 1; i <= 3; i++) {
    for (int j = 1; j <= 3; j++) {
        if (j == 2) {
            break;          // Solo sale del bucle de j
        }
        System.out.println(i + "x" + j);
    }
}
    Resultado 
    1x1
2x1
3x1

    Para salir de ambos, necesitarás una etiqueta (§6.4).

    6.2. continue: saltar a la siguiente iteración

    continue termina la iteración actual y pasa directamente a la siguiente, sin ejecutar el resto del cuerpo del bucle.

    1
2
3
4
5
6
    for (int i = 0; i < 10; i++) {
    if (i == 6) {
        continue;
    }
    System.out.println("i: " + i);
}
    Resultado 
    i: 0
i: 1
i: 2
i: 3
i: 4
i: 5
i: 7
i: 8
i: 9

    Fíjate en la diferencia con el apartado anterior: aquí el bucle sí completa las 10 iteraciones. Solo se salta la impresión del 6.

    Cuándo es más legible continue que un if enorme

    Si tienes un if con muchas condiciones para el caso "no hacer nada", invierte la lógica y usa continue:

    // ❌ Legible, pero con el caso "nada que hacer" al final
for (String linea : lineas) {
    if (linea != null && !linea.isBlank()) {
        procesar(linea);
    }
}

    // ✅ Se lee de arriba abajo: "si no vale, sáltatelo"
for (String linea : lineas) {
    if (linea == null || linea.isBlank()) {
        continue;
    }
    procesar(linea);
}

    continue en un while puede provocar un bucle infinito

    En un while, el continue salta a la comprobación de la condición. Si la condición sigue siendo verdadera y no hay nada que la modifique, el bucle nunca termina.

    int numero = 0;
while (numero < 10) {
    continue;               // ❌ numero nunca cambia: infinito
}

    En un for, el continue sí ejecuta la sección de iteración (i++), así que el bucle avanza con normalidad.

    6.3. return: terminar un método

    return termina la ejecución del método en el que aparece. Hay dos formas de usarlo:

    Forma Qué hace
    return valor; Termina el método devolviendo un valor del tipo declarado en la cabecera.
    return; Termina el método sin devolver ningún valor (solo válido si el método es void).

    En ambos casos, el control pasa a la instrucción siguiente a la llamada del método.

    1
2
3
4
5
6
7
8
9
    public static int suma(int a, int b) {
    int resultado = a + b;
    return resultado;
}

public static void main(String[] args) {
    int total = suma(3, 7);
    System.out.println("La suma es: " + total);   // 10
}

    return como salida anticipada (early return)

    Un return bien colocado puede simplificar un programa con muchos niveles de anidamiento:

    // Antes: tres niveles de if anidados
if (edad >= 18) {
    if (tieneCarnet) {
        System.out.println("Acceso permitido");
    } else {
        System.out.println("Falta el carnet");
    }
} else {
    System.out.println("Menor de edad");
}

    // Después: caso base primero, casos especiales después
if (edad < 18) {
    System.out.println("Menor de edad");
    return;
}
if (!tieneCarnet) {
    System.out.println("Falta el carnet");
    return;
}
System.out.println("Acceso permitido");

    Esta técnica se llama salida anticipada y es de las más usadas en código profesional. Reduce el anidamiento y hace que cada caso se lea en una sola línea.

    Por regla general, un solo return

    Aunque Java permite varios return en un método, lo habitual es que el último (o único) esté al final. Los múltiples return se consideran "efectos colaterales" y complican la lectura. Úsalos solo con la técnica de salida anticipada.

    6.4. Etiquetas de salto

    Java permite etiquetar un bucle para poder romperlo desde un nivel superior. La sintaxis es etiqueta: bucle.

    1
2
3
4
5
6
7
8
9
    salida:                       // Etiqueta puesta antes del for exterior
for (int i = 1; i <= 10; i++) {
    for (int j = 1; j <= 10; j++) {
        if (i * j > 40) {
            break salida;     // Sale del bucle EXTERIOR, no del interior
        }
        System.out.println(i + " x " + j + " = " + (i * j));
    }
}
    Resultado 
    1 x 1 = 1
1 x 2 = 2
…
1 x 7 = 7
2 x 1 = 2
…
5 x 9 = 45 → break sale en i=5, j=9

    El programa termina todo el bucle exterior en cuanto i * j supera 40.

    Las etiquetas son código de último recurso

    Las etiquetas son la forma más rápida de convertir un programa legible en un laberinto. Úsalas solo cuando:

    • el break normal no basta (necesitas salir de bucles anidados), y
    • no hay una forma más limpia de evitar el anidamiento.

    Alternativa moderna: antes de etiquetar, pregunta a tu profesor si espera la solución modular (extraer el bucle interior a un método).

    6.5. Resumen comparativo

    Sentencia Ámbito Efecto
    break Bucle o switch actual Sale de la estructura
    break etiqueta Bucle etiquetado Sale del bucle etiquetado
    continue Bucle actual Salta a la siguiente iteración
    return Método actual Sale del método (devolviendo valor o no)
    continue etiqueta Bucle etiquetado Salta a la siguiente iteración del bucle etiquetado

    Prueba esto

    Añade un System.out.println("Sigo aquí") justo después de cada break y continue de los ejemplos. Ejecuta el programa y observa dónde se interrumpe el flujo. Es la forma más rápida de entender qué hace cada sentencia.
