    2. Control del flujo de ejecución

    Hasta ahora tus programas se ejecutaban siempre igual: la instrucción 1, luego la 2, luego la 3… Como una lista de tareas que haces siempre en el mismo orden. Esa es la estructura de secuencia.

    En esta unidad aprendes a decidir y a repetir. Con ello tus programas dejan de ser guiones fijos y se convierten en algo que responde a lo que pasa.

    2.1. Las tres estructuras de control

    Las tres estructuras básicos del control de flujo

    Toda la materia de esta unidad se reduce a tres estructuras. Las dos nuevas se construyen siempre sobre la primera.

    Estructura Qué hace Palabras clave en Java
    Secuencia Ejecuta las sentencias en el orden en que están escritas. (ninguna: es el orden natural)
    Selección Evalúa una condición y decide qué sentencias ejecutar. if · else · switch
    Iteración Evalúa una condición y decide cuántas veces repetir unas sentencias. while · do…while · for

    La analogía del fontanero. Un fontanero no trabaja con agua: la mueve. Tuerce una tubería para que el agua vaya por donde quiere, coloca una llave de paso para abrir y cerrar el caudal, y monta un purgador para que el agua circule. En programación:

    • las tuberías son las sentencias,
    • las llaves de paso son las condiciones,
    • los purgadores son los bucles.

    El error conceptual más habitual

    Muchos estudiantes creen que un if "hace que el programa espere" o que un while "hace que el programa piense". No: un if no hace nada, solo decide qué camino tomar. Y un while no espera: repite un bloque de código.

    2.2. Sentencias y bloques

    Preguntas frecuentes

    • ¿Puedo escribir varias sentencias en una línea separadas por ;? Sí, compila, pero no lo hagas: cuando el programa falle, el compilador te dará un número de línea y no sabrás dónde está el error.
    • ¿Una sentencia puede ocupar varias líneas? Sí. Toda sentencia termina en ;, esté donde esté.
    • ¿Detrás de la cabecera de un if va un ;? No. Este es el error más común al escribir un if de una sola línea: if (x > 0); es una sentencia nula, y el cuerpo real queda fuera de la condición.

    La sentencia nula es una línea que solo contiene ;. No hace nada, pero es legal.

    El ; traicionero

    if (edad >= 18);      // ERROR LÓGICO: el punto y coma cierra el if aquí
    System.out.println("Mayor de edad");

    El programa compila (el if recibe la sentencia nula y el println se ejecuta siempre), pero hace justo lo contrario de lo que querías. Usa siempre llaves.

    El bloque de sentencias es un conjunto de sentencias entre llaves {} que se ejecutan como si fueran una sola:

    { System.out.println("Hola"); System.out.println("Adiós"); }

    {
    System.out.println("Hola");
    System.out.println("Adiós");
}

    Regla práctica

    Pon llaves siempre, aunque el cuerpo sea una sola instrucción. La llave te ahorra un ; traicionero y te ahorra un else que se adosa al if equivocado.

    2.3. Tres organizaciones, un mismo resultado

    Estos tres programas hacen exactamente lo mismo. Solo cambia dónde están declaradas las variables y cómo se agrupan las sentencias.

    int dia = 12;
System.out.println("El día es: " + dia);
int mes = 11;
System.out.println("El mes es: " + mes);
int anio = 2026;
System.out.println("El año es: " + anio);

    int dia = 12;
int mes = 11;
int anio = 2026;
System.out.println("El día es: " + dia);
System.out.println("El mes es: " + mes);
System.out.println("El año es: " + anio);

    // 1. Declaración de variables
int dia, mes, anio;

// 2. Entrada de datos
dia = 12;
mes = 11;
anio = 2026;

// 3. Procesamiento
String fecha = dia + "/" + mes + "/" + anio;

// 4. Salida
System.out.println("La fecha es: " + fecha);

    La organización que usamos en el curso

    La tercera es la que debes escribir siempre: separas declaración, entrada, procesamiento y salida. Cuando incorpores if y bucles, esa separación te va a resultar muy útil: el bloque de entrada será el while, el de procesamiento el if.

    2.4. Ámbito de las variables dentro de un bloque

    Una variable declarada dentro de un bloque solo existe dentro de ese bloque. Es una regla que en UD01 no se notaba, porque todo estaba en el mismo nivel.

    1
2
3
4
5
6
    if (true) {
    int edad = 22;          // La variable edad SOLO existe dentro de las llaves
    System.out.println(edad);
}

System.out.println(edad);   // ERROR: no compila, edad no existe aquí

    Variable declarada dentro de un if o un for

    Esto es legal y muy útil, pero conviene saberlo: el contador de un for declarado en la cabecera (for (int i = 0; …)) desaparece al terminar el bucle.

    for (int i = 0; i < 5; i++) {
    System.out.println(i);
}
System.out.println(i);   // ERROR: i no existe fuera del bucle

    Si necesitas el contador después, decláralo antes:

    int i;
for (i = 0; i < 5; i++) {
    System.out.println(i);
}
System.out.println("El bucle terminó con i = " + i);   // i = 5

    Puente con UD03

    Este mismo bloque {} es la base de los métodos. Cuando en UD03 declares tus propios métodos, cada uno será un bloque con entrada y salida. Por eso es tan importante entender el ámbito.
