    import java.util.Scanner;

/*
 * Programa que calcula un descuento sobre el precio de un producto.
 */
public class Descuento {

    public static final float DESCUENTO = 8;
    public static final float COMPRA_MIN = 100;

    public static void main(String[] args) {
        Scanner lector = new Scanner(System.in);

        System.out.print("¿Cuál es el precio del producto, en euros? ");
        float precio = lector.nextFloat();
        lector.nextLine();

        if (precio >= COMPRA_MIN) {
            float descuento = precio * DESCUENTO / 100;
            precio = precio - descuento;
        }

        System.out.println("El precio final para pagar es de " + precio + " euros.");
        lector.close();
    }
}

    public class Modulo {
    public static void main(String[] args) {
        Scanner lector = new Scanner(System.in);

        System.out.print("¿Cuál es el dividendo? ");
        int dividendo = lector.nextInt();
        lector.nextLine();

        System.out.print("¿Cuál es el divisor? ");
        int divisor = lector.nextInt();
        lector.nextLine();

        int cociente = 0;
        while (dividendo >= divisor) {
            dividendo = dividendo - divisor;
            cociente++;
        }

        System.out.println("Cociente: " + cociente);
        System.out.println("Resto: " + dividendo);
        lector.close();
    }
}

    Pista: el contador cociente ya es la división entera. El dividendo que queda al final es el resto.

    Reto 23 · Cadenas de if-else

    ¿Qué valor se asigna a consumo si velocidad es 120?

    if (velocidad > 80)
    consumo = 10;
else if (velocidad > 100)
    consumo = 12;
else if (velocidad > 120)
    consumo = 15;
    Solución

    Se asigna consumo = 10.

    Las condiciones se evalúan de arriba abajo y se detiene en la primera verdadera. 120 > 80 es cierto, así que entra en la primera rama y nunca llega a comprobar las demás.

    Este es el error más frecuente con cadenas else if: el orden importa. Si la primera condición es demasiado general, las otras nunca se ejecutan.

    Reto 24 · Encuentra y corrige los errores

    Corrige estos tres fragmentos:

    a) Faltan paréntesis y un punto y coma:

    if x > 25 y = x
else
    y = z;

    b) El else se ha descolgado del if incorrecto:

    if (x < 0)
    System.out.println("El valor de x es " + x);
    System.out.println("x es negativo");
else
    System.out.println("El valor de x es " + x);
    System.out.println("x es positivo");

    c) Se ha usado asignación en lugar de comparación:

    if (x = 0)
    System.out.println("x igual a cero");
else
    System.out.println("x distinto de cero");
    Respuestas

    a) Faltan los paréntesis de la condición y el ; tras la asignación:

    if (x > 25)
    y = x;
else
    y = z;

    b) El println de la línea 3 queda fuera del if porque no tiene llaves. Con x = -5 se impresión las dos líneas. El arreglo son las llaves:

    if (x < 0) {
    System.out.println("El valor de x es " + x);
    System.out.println("x es negativo");
} else {
    System.out.println("El valor de x es " + x);
    System.out.println("x es positivo");
}

    c) x = 0 es una asignación: la condición siempre es cierta (el valor 0 convertido a boolean es false... y ahí está el fallo). Debe ser x == 0.

    Determina la salida exacta de este programa con x = 20:

    int x = 20;
System.out.println("Comenzamos");

if (x >= 20)
    if (x > 50)
        System.out.println("Muy grande");
    else {
        if (x % 2 != 0)
            System.out.println("Impar");
    }
else if (x <= 20)
    System.out.println("Pequeño");

System.out.println("Terminamos");
    Solución 
    Comenzamos
Terminamos

    No imprime nada en medio. Es el else suspendido del §3.4: el else se asocia al if (x > 50) interior, no al exterior. Como 20 >= 20 es cierto, se entra al bloque; 20 > 50 es falso; y 20 % 2 != 0 es falso. El else if (x <= 20) exterior queda sin ejecutar.

    Solución: añade llaves.

    Reto 26 · Descuentos por tramos

    En una tienda se aplican descuentos por tramos:

    • Total < 500 € → sin descuento
    • 500 € ≤ total ≤ 2000 € → 30 %
    • Total > 2000 € → 50 %

    Indica cuál de los cuatro fragmentos asigna el descuento correcto:

    a)

    double desc = 0.0;
if (total <= 500)
    if (total >= 2000) desc = 30.0;
    else desc = 50.0;

    b)

    double desc = 0.0;
if (total >= 500)
    if (total <= 2000) desc = 30.0;
    else desc = 50.0;

    c)

    double desc = 0.0;
if (total <= 2000) {
    if (total >= 500) desc = 30.0;
} else desc = 50.0;

    d)

    double desc = 0.0;
if (total > 500)
    if (total < 2000) desc = 30.0;
    else desc = 50.0;
    Solución

    Las correctas son la b) y la c).

    Caso Correcto a b c d
    300 0 % 50 ❌ 0 ✅ 0 ✅ 0 ✅
    500 30 % 50 ❌ 30 ✅ 30 ✅ 0 ❌
    2000 30 % 0 ❌ 30 ✅ 30 ✅ 50 ❌
    2001 50 % 0 ❌ 50 ✅ 50 ✅ 50 ✅
    • La a) está invertida: entra en el if cuando el total es pequeño, y aplica el 50 % justo en el caso que no lleva descuento.
    • La d) falla justo en los dos bordes: con total = 500 la condición total > 500 es falsa, y con total = 2000 la condición total < 2000 también es falsa. Por eso devuelve 0 % y 50 % respectivamente.

    Los cuatro coinciden en el centro del rango y solo fallan en los extremos. Por eso hay que probar los límites, no solo el centro.

    Determina qué imprime este programa con platos = 1, con platos = 3 y con platos = 0:

    case 1: System.out.println("Primer plato");

    Reto 28 · Traducir un análisis a Java

    Este pseudocódigo establece el valor de p a partir de tres enteros:

    si a > b entonces p = cierto
si a < b entonces p = falso
si a = b entonces
    si a > c entonces p = cierto
    si a < c entonces p = falso
    si a = c entonces p = falso

    Tradúcelo a Java de tres maneras distintas:

    1. Con un único if sin anidamiento.
    2. Con una única instrucción p = … sin if y sin operador ternario.
    3. Con una única instrucción p = … que sí use el operador ternario.
    Solución orientativa

    1. Con else if, aprovechando que los rangos son excluyentes:

    if (a > b) p = true;
else if (a < b) p = false;
else if (a > c) p = true;
else p = false;

    2. Con una sola asignación y operadores lógicos, sin ninguna estructura condicional. El pseudocódigo se traduce literalmente:

    p = (a > b) || (a == b && a > c);

    Compruébalo caso a caso: si a > b, el primer sumando ya es cierto y p vale true. Si a < b y a > b es falso, también a == b es falso, luego p = false. Solo queda a == b, donde decide a > c.

    Ojo: a != b no sirve, porque entonces p sería true también cuando a < b, que es justo el caso que debe dar false.

    3. Con el operador ternario en una escalera:

    p = (a > b) ? true
  : (a < b) ? false
  : (a > c) ? true
  : false;

    Las tres son correctas. La primera es más legible, la tercera más compacta. Elige según el contexto.
