    14. Errores frecuentes y cómo solucionarlos

    14.1. Errores de compilación

    # Mensaje de error Causa Solución
    1 ';' expected Falta el punto y coma al final de una instrucción. Añádelo. Cada sentencia termina en ;.
    2 illegal start of expression Un ; de más, normalmente tras la cabecera de un if o de un for. Quítalo. Detrás de la cabecera no va punto y coma.
    3 ';' expected tras } while (condicion) Falta el ; final del do…while. El único do…while que exige punto y coma.
    4 class, public, or interface expected Suele faltar un ; en la línea anterior a la que indica el compilador. Revisa la línea anterior.
    5 reached end of file while parsing Faltan llaves } de cierre. Cuenta { y }. Usa el sangrado automático del editor.
    6 variable might not have been initialized Variable local usada antes de asignarle valor. Inicialízala antes de usarla.
    7 cannot find symbol Nombre mal escrito. Java distingue mayúsculas. Revisa ortografía y mayúsculas.
    8 incompatible types: possible lossy conversion Asignas un double a un int sin cast. Añade (int) o declara la variable como double.
    9 bad operand types for binary operator '+' Mezclas tipos que no se pueden sumar, normalmente sin paréntesis. Usa paréntesis: "Total: " + (a + b).
    10 switch con double El switch clásico no admite float ni double. Usa if-else, o cambia a switch de cadenas.
    11 unclosed string literal Te falta la comilla de cierre " o el ; final. Revisa las comillas de las cadenas.
    12 non-static method … cannot be referenced from a static context Intentas llamar a un método de instancia desde main. Añade static al método, o quita el static a la clase.

    14.2. Errores de lógica (el programa compila pero hace otra cosa)

    Estos son mucho más peligrosos, porque el programa se ejecuta y devuelve datos equivocados.

    # Síntoma Causa habitual Cómo diagnosticarlo
    1 La condición nunca se cumple Usaste = en lugar de == Revisa las comparaciones una a una
    2 Un if no hace nada Hay un ; detrás de la cabecera Busca if (...);
    3 La media sale con decimales a 0 División entera: suma / contador con int Escribe (double) suma / contador
    4 Un else se ejecuta cuando no debería else suspendido Pon llaves en todos los if
    5 El switch ejecuta casos de más Falta un break (fall-through) Revisa cada case
    6 El bucle no termina La condición nunca se hace falsa Imprime el contador en cada vuelta
    7 El bucle se ejecuta 0 veces La condición es falsa desde el principio Revisa el valor inicial del contador
    8 El bucle se ejecuta una vez de más Usaste < en lugar de <= Comprueba los límites
    9 Un for con continue no avanza En un while, el continue salta el incremento Mueve el incremento antes del continue
    10 El máximo siempre vale 0 Inicializaste a 0 en vez de Integer.MIN_VALUE Revisa el valor inicial
    11 Falla solo con algunos datos No has probado los casos límite Haz la tabla de decisión

    14.3. Errores en tiempo de ejecución

    # Mensaje Causa Solución
    1 ArithmeticException: / by zero División entre cero. Comprueba el divisor antes de dividir.
    2 InputMismatchException El usuario escribió letras donde se esperaba un número. Se resuelve en UD07 con try/catch.
    3 StringIndexOutOfBoundsException charAt() o substring() fuera del rango de la cadena. Comprueba length() antes de acceder.
    4 StackOverflowError Recursión infinita sin caso base. Se estudia en UD03.
    5 El programa se queda colgado Bucle infinito. Pulsa ■ en Eclipse para ver la traza de pila.
    6 AssertionError Una aserción ha fallado. El mensaje indica qué comprobación se incumplió.

    Herramientas de depuración

    • Punto de interrupción (F9): haz clic a la izquierda de la línea y ejecuta en modo depuración (F11 o el icono del insecto), no con F5.
    • Step Over (F8): avanza una línea ejecutando los métodos por dentro.
    • Inspección de variables: pasa el ratón sobre cualquier variable con el programa detenido.
    • Traza de pila: cuando el programa falla, el primer bloque de texto te dice exactamente en qué línea.

    El depurador no sustituye a la traza en papel

    Puedes depurar cualquier programa con un depurador, pero la traza escrita es la única forma de comprobar que entiendes el código. Y entender el código es justo lo que se evalúa.
