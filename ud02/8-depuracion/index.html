    8. Depuración de programas

    Depurar es encontrar la causa exacta de un error. Se hace desde dentro del programa, observando su estado paso a paso.

    Estrategia sistemática de depuración

    1. Reproduce el fallo de forma controlada, con los datos que lo provocan.
    2. Localiza la línea exacta donde el valor deja de ser el esperado (no la zona: la línea).
    3. Explica por qué. Si no puedes explicar la causa, todavía no la has encontrado.
    4. Corrige y vuelve a probar con el mismo caso.
    5. Repite la prueba con los demás casos: corregir un error puede crear otro.

    El error que todos cometemos

    Cambiar cosas al azar hasta que funcione. Se llama depuración por ensayo y error y no funciona: funciona una vez y rompe otra. Depurar es medir, no adivinar.

    8.1. El depurador: tu microscopio

    Un depurador (debugger) es una herramienta que ejecuta el programa de forma controlada y te deja verlo por dentro. Todos los IDE lo tienen integrado.

    ¿Cómo funciona?

    Colocas puntos de interrupción en las líneas que te interesan. Cuando el programa llega a una de ellas, se detiene y te deja examinar todas las variables, una a una, y avanzar línea a línea.

    Puntos de interrupción

    Se colocan haciendo clic en el margen izquierdo de la línea, o pulsando F9 con el cursor sobre la línea.

    Recuerda activar el modo depuración

    Pulsar F5 (o el botón ▶️) ejecuta de forma normal y se salta los puntos de interrupción. Necesitas F11 o el icono del insecto (🐞) para depurar de verdad.

    Atajo (Eclipse / VS Code) Acción
    F8 Step Over: ejecuta la línea actual y salta a la siguiente
    F7 Step Into: entra dentro del método llamado
    F6 Step Out: sale del método actual
    F9 Alterna el punto de interrupción en la línea actual
    F5 Inicia / reinicia la sesión de depuración

    Inspección de variables

    Con el programa detenido, pasa el ratón por encima de cualquier variable y aparecerá su valor. También puedes:

    • hacer doble clic en el valor para editarlo en caliente (útil para forzar una rama),
    • usar la vista Variables de Eclipse, que muestra todas las de ámbito local,
    • añadir expresiones de vigilancia (watch expressions) para seguir un valor concreto.

    8.2. Depurar un if mal construido

    El siguiente programa no hace lo que parece. Depúralo:

    1
2
3
4
5
6
7
8
9
    int nota = 4;
String resultado;

if (nota >= 5);
    resultado = "Aprobado";
else
    resultado = "Suspendido";

System.out.println(resultado);
    Qué ocurre realmente

    Imprime Aprobado, que es incorrecto: una nota de 4 debería ser Suspendido.

    La causa es el ; de la línea 4. El if recibe como cuerpo una sentencia nula (;), así que la condición no controla nada. El resultado = "Aprobado" se ejecuta siempre, y el else se descolga porque ya no hay if al que adscribirse.

    Traza del flujo:

    Línea Qué ocurre
    3 nota = 4
    4 Se evalúa nota >= 5 → false. Pero el cuerpo es ;, no importa el resultado
    5 Se ejecuta resultado = "Aprobado"
    7 El else ya no tiene if al que adscribirse: error de compilación en realidad

    En realidad esto no compila: el else no se puede adscribir al if cuyo cuerpo es la sentencia nula, porque la gramática de Java no permite un else sin if asociado. El compilador da el error else without if.

    La corrección es quitar el punto y coma y usar llaves:

    if (nota >= 5) {
    resultado = "Aprobado";
} else {
    resultado = "Suspendido";
}

    Lección

    Este es el motivo por el que en toda la unidad insistimos en llaves siempre. Un ; de más no da un error de compilación claro: da un programa que hace lo contrario.

    8.3. Depurar un bucle infinito

    Síntoma: el programa no termina y la consola se llena de líneas.

    Método 1 · Interruptor de Eclipse

    Pulsa el botón ■ (cuadrado rojo) en la consola. Se abrirá una ventana con una traza de pila (stack trace) que te dice exactamente en qué línea estás dentro del bucle.

    Lee la traza de pila de abajo arriba

    La última línea dice desde dónde llamaste al método. Las anteriores dicen por dónde se ha ejecutado. La línea que esté dentro de tu bucle es donde se ha quedado el programa.

    Método 2 · Impresión de diagnóstico

    Si no te basta con el depurador, añade un println temporal dentro del bucle:

    1
2
3
4
5
    int i = 0;
while (i < 10) {
    System.out.println("Iteración " + i);
    i++;                    // ← ¿está esta línea?
}

    Si el programa imprime Iteración 0 miles de veces, la variable que controla el bucle no se está modifica. Añade la impresión, ejecútalo, y la primera línea que se repita te dice el problema.

    Elimina las Prints de diagnóstico después

    Un println de diagnóstico que se queda en el código es ruido. Cuando el bug esté localizado y corregido, bórralo. Como mucho, déjalo en un comentario: // System.out.println("aquí falla");

    8.4. Errores de lógica vs. errores de sintaxis

    ¿El programa compila pero hace algo raro? Es un error de LÓGICA.

    Tipo Qué es Cómo se detecta
    Error de sintaxis El código no cumple las reglas del lenguaje. El compilador lo dice con número de línea.
    Error de semántica / lógica El código cumple las reglas pero hace algo que no querías. El programa compila y produce un resultado incorrecto.

    El error de lógica es el peligroso

    Un error de sintaxis te detiene en seco: lo ves enseguida. Un error de lógica te deja seguir trabajando con un programa que devuelve datos equivocados, y si no lo detectas, se propaga a todo lo demás.

    De ahí la importancia del punto 3 de la estrategia: explicar por qué. Si no puedes explicar en una frase por qué el resultado es incorrecto, todavía no sabes dónde está el fallo.

    8.5. Herramientas de apoyo

    Herramienta Para qué sirve
    Punto de interrupción Congela el programa en una línea concreta.
    Step Over / Into / Out Avanza línea a línea, entrando o saliendo de métodos.
    Inspección de variables Mira el valor de cualquier variable en caliente.
    Consola (Println) Imprime valores para seguir el flujo. Cuando el depurador no basta.
    Traza de pila Indica la línea exacta donde se produjo una excepción.
    Java Tutor (online) Dibuja la ejecución paso a paso de un programa. Excelente para aprender.

    Puente con el mundo real

    El depurador no es una herramienta de aprendizaje: es una herramienta de trabajo. En la empresa se depura código que no has escrito tú, de miles de líneas, hecho por otras personas. Por eso conviene acostumbrarse a usarlo cuanto antes, y no solo durante la unidad.
