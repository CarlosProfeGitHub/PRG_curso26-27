    5. Estructuras de repetición

    Hasta ahora tus programas ejecutaban cada sentencia una vez. Las estructuras de repetición permiten ejecutar un bloque de sentencias tantas veces como haga falta, controlando el número de repeticiones con una condición.

    Las cuatro estructuras de Java

    Bucle Se usa cuando… Tipo
    for Sabes cuántas veces hay que repetir. Controlado por contador
    while Hay que repetir mientras se cumpla una condición (puede no repetirse ni una vez). Controlado por suceso
    do … while Hay que repetir hasta que se cumpla una condición (se repite al menos una vez). Controlado por suceso
    for-each Hay que recorrer un array o una colección. Controlado por contador

    5.1. La pregunta clave antes de elegir bucle

    Pregunta Bucle
    ¿Sé cuántas veces debo repetir? for
    ¿Mientras se cumpla esta condición? while
    ¿Necesito que se ejecute al menos una vez? do … while
    ¿Quiero recorrer una lista de elementos? for-each

    Son equivalentes entre sí

    Los cuatro bucles pueden resolver el mismo problema. Un for se puede escribir como while y viceversa. Lo que cambia no es lo que el programa calcula, sino cómo de legible es el código. Elegir mal el bucle no es un error, pero sí una falta de estilo.

    5.2. El bucle for

    Tres operaciones, todas en la cabecera:

    for (inicialización; condición; iteración) {
    cuerpo;
}
    Parte Función
    inicialización Declara e inicializa la variable de control. Se ejecuta una sola vez.
    condición Se evalúa antes de cada iteración. Mientras sea true, el cuerpo se repite.
    iteración Actualiza la variable de control. Se ejecuta después de cada vuelta.

System.out.println("Tabla de multiplicar del " + numero);
System.out.println("-----------------------------");

for (int i = 1; i <= 10; i++) {

    El orden de evaluación, paso a paso

    Con for (int i = 1; i <= 10; i++):

    1. int i = 1 → el cuerpo se ejecuta
    2. se comprueba i <= 10
    3. i++ → i = 2 → el cuerpo se ejecuta
    4. se comprueba i <= 10
    5. …

    El bucle termina cuando i vale 11: la condición es falsa y el cuerpo no se ejecuta. Por eso el último número impreso es el 10, no el 11.

    i++ puede ser cualquier cosa

    No hace falta ir de uno en uno:

    for (int i = 0; i <= 20; i += 5)   // 0, 5, 10, 15, 20
for (int i = 10; i > 0; i -= 2)    // 10, 8, 6, 4, 2

    5.3. El bucle while

    Repite el cuerpo mientras la condición sea verdadera. La condición se evalúa antes, así que el cuerpo puede no ejecutarse nunca.

    import java.util.Scanner;

Scanner teclado = new Scanner(System.in);
int numero;

System.out.print("Introduce un número: ");
numero = teclado.nextInt();

while (numero <= 500) {
    System.out.println("Introduce otro número: ");
    numero = teclado.nextInt();
}

System.out.println("Fin del bucle");
teclado.close();
    Resultado 
    Introduce un número: 400
Introduce otro número: 900
Fin del bucle

    La condición DEBE cambiar dentro del bucle

    Si la condición no se modifica, el bucle no termina nunca. Es el error de programación más costoso de diagnosticar, porque el programa no falla: se queda congelado.

    int x = 5;
while (x == 5) {              // ❌ x nunca cambia: bucle infinito
    System.out.println("Sigo aquí");
}

    int x = 5;
while (x == 5) {              // ✅ ahora sí, x se modifica
    System.out.println("Sigo aquí");
    x++;
}

    5.4. El bucle do … while

    La diferencia con while está en dónde se evalúa la condición. En do…while se evalúa después: el cuerpo se ejecuta al menos una vez, siempre.

    import java.util.Scanner;

Scanner teclado = new Scanner(System.in);
int numero;

do {
    System.out.print("Introduce un número: ");
    numero = teclado.nextInt();
} while (numero <= 500);

System.out.println("Fin del bucle");
teclado.close();
    Resultado 
    Introduce un número: 900
Fin del bucle

    Fíjate: con 900 el bucle termina después de haber leído el número. Con un while normal, el 900 ni siquiera se habría pedido.

    Aspecto while do … while
    Momento de la condición Antes del cuerpo Después del cuerpo
    Veces mínima de ejecución 0 1
    ; final No Sí, obligatorio tras while (condición)

    El ; del do … while es obligatorio

    } while (condicion);     // ← este punto y coma es obligatorio

    Es el único caso del lenguaje donde el punto y coma no es opcional, y olvidarlo da un error de compilación bastante críptico.

    5.5. for-each: recorrer arrays y colecciones

    El bucle for-each (también for-in) permite recorrer un array o una colección sin controlar el índice.

    1
2
3
4
5
    int[] numeros = {0, 1, 2, 3, 4};

for (int numero : numeros) {
    System.out.println(numero);
}
    Elemento Significado
    int numero Variable que recibe el valor de cada elemento. Su tipo debe coincidir con el del array.
    numeros El array o colección que se recorre.

    Lo verás en la UD04

    Los arrays se introducen en UD04 · Estructuras de datos estáticos. Aquí basta con saber que la estructura existe y cuál es su sintaxis, porque necesitarás un array para resolver algunas actividades de la unidad.

    Ventaja del for-each

    No te puedes equivocar con los límites del array: no hay i <= numeros.length que pueda quedar mal escrito. Pero no puedes modificar el tamaño del array ni salir antes de tiempo con break sobre una estructura de datos completa.

    5.6. Contadores y acumuladores

    Los dos ingredientes de casi cualquier bucle:

    Concepto Qué es Ejemplo
    Contador Variable que lleva la cuenta de las iteraciones. Suele empezar en 0 o 1 y aumentar en 1. int cont = 0; … cont++;
    Acumulador Variable que guarda el resultado parcial que se va sumando. Suele empezar en 0. int suma = 0; … suma += n; 
    1
2
3
4
5
6
7
8
    // Contador: cuenta cuántos números pares hay del 1 al 10
int contadorPares = 0;
for (int i = 1; i <= 10; i++) {
    if (i % 2 == 0) {
        contadorPares++;
    }
}
System.out.println("Pares: " + contadorPares);   // 5

    El acumulador debe empezar en 0 (o en el valor neutro de la operación)

    Si inicializas el acumulador con un valor cualquiera, el resultado será incorrecto:

    int suma = 5;              // ❌ 5 no es el valor neutro de la suma
for (int i = 1; i <= 4; i++) {
    suma += i;
}
// suma vale 15, pero 1+2+3+4 = 10

    Y si lo declaras con el valor que quieres al principio, necesitas dos variables: el acumulador y la suma final.

    5.7. Bucles infinitos

    Un bucle es infinito cuando su condición nunca se vuelve falsa. Ocurre por tres motivos habituales:

    // ❌ i baja de 5 a 3, 1, -1, -3… nunca pasa por 0
for (int i = 5; i != 0; i -= 2) {
    System.out.println(i);
}

    Con números impares, i nunca vale exactamente 0. La solución es comparar con un rango:

    for (int i = 5; i > 0; i -= 2) {   // ✅
    System.out.println(i);
}

    int x = 5;
while (x == 5) {              // ❌ x nunca cambia
    System.out.println("En el bucle");
}

    Scanner teclado = new Scanner(System.in);
int numero;

do {
    System.out.print("Introduce un número: ");
    numero = teclado.nextInt();
} while (numero != 0);       // ❌ si el usuario teclea 999999999, no sale

// ✅ Mejor: una condición que el usuario pueda cumplir
do {
    System.out.print("Introduce un número entre 1 y 10: ");
    numero = teclado.nextInt();
} while (numero < 1 || numero > 10);

    Cómo salir de un bucle infinito sin usarse

    En Eclipse, haz clic en la flecha roja pequeña (■) de la consola. En VS Code, pulsa Ctrl + C en la terminal.

    Y para probarlo sin quedarte colgado, siempre pon un tope:

    int limite = 0;
while (true) {
    limite++;
    if (limite > 1000) {
        System.out.println("Salgo por seguridad");
        break;
    }
}

    5.8. Anidamiento de bucles

    Un bucle puede ir dentro de otro. El exterior controla las filas y el interior, las columnas.

    1
2
3
4
5
6
    for (int fila = 1; fila <= 3; fila++) {
    for (int col = 1; col <= 4; col++) {
        System.out.print(fila * col + "\t");
    }
    System.out.println();     // Salto de línea al final de cada fila
}
    Resultado 
    1   2   3   4
2   4   6   8
3   6   9   12

    El coste del anidamiento

    Un bucle de 1000 iteraciones que contiene otro de 1000 itera un millón de veces. Antes de anidar dos bucles, pregúntate si puedes resolverlo con uno solo. Suele ser posible.

    Puente con UD03

    Cuando el bucle interior sea siempre el mismo, se extraerá a un método. Esa extracción es lo que se llama refactorización y es el primer paso de la programación modular, que veremos en UD03.
