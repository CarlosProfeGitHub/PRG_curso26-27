    9. Documentación y aserciones

    Este apartado cubre los criterios de evaluación g) Se ha comentado y documentado el código e i) Se han utilizado asertos para la detección y corrección de errores durante la fase de desarrollo.

    En UD01 viste los tres tipos de comentarios. Ahora se aplica en la práctica: cómo documentar un programa que tiene estructuras de control, y cómo verificar con assert que esas estructuras hacen lo que deben.

    9.1. La diferencia entre comentar y documentar

    Acción Para quién Cuándo
    Comentar Para quien lee el código. Mientras escribes.
    Documentar Para quien usa el programa (sin ver el código). Al terminar.

    Regla práctica

    El código dice qué hace. El comentario dice por qué lo hace.

    // ❌ No aporta nada: repite lo que ya se ve
// Incrementa el contador
contador++;

// ✅ Explica la decisión que el código no puede expresar
// Cada error anula media respuesta correcta (norma del departamento)
nota = ((aciertos - (errores / 2)) * 10) / preguntas;

    9.2. La cabecera del programa

    Todo programa de entrega empieza con una cabecera que responde a cuatro preguntas. Este formato es el que debes usar.

    /*
 * Programa: CalculaIMC
 * Descripción: Pide peso y altura por teclado y calcula el
 *              índice de masa corporal, clasificando el
 *              resultado según la escala de la OMS.
 * Autor: [Tu nombre]
 * Fecha: 2026-10-15
 */

    /**
 * Calcula el índice de masa corporal (IMC) de una persona.
 *
 * @param peso    peso en kilogramos
 * @param altura  altura en metros
 * @return el valor del IMC
 */
public static double calculaIMC(double peso, double altura) {
    return peso / Math.pow(altura, 2);
}

    La fecha es la última modificación

    Cuando corrijas algo dentro de tres semanas, actualiza la fecha. Una cabecera con una fecha antigua es peor que no tener cabecera: engaña.

    9.3. Cómo documentar las estructuras de control

    Un if o un bucle sin comentario es donde se pierde el tiempo de quien lee tu código. Estas son las convenciones que usamos en el curso.

int contador = 0;
int suma = 0;

// ---------- 2. LECTURA DE DATOS ----------
Scanner teclado = new Scanner(System.in);
System.out.print("¿Cuántos números quieres sumar? ");
int cantidad = teclado.nextInt();

// ---------- 3. PROCESO ----------
for (int i = 1; i <= cantidad; i++) {
    System.out.print("Número " + i + ": ");
    int numero = teclado.nextInt();
    suma += numero;          // Acumulador
    contador++;              // Contador
}

// ---------- 4. SALIDA DE INFORMACIÓN ----------
System.out.println("Has introducido " + contador + " números");
System.out.println("Su suma es: " + suma);

teclado.close();

    Explica las condiciones complejas

    Cuando una condición tiene varios && u ||, un comentario con el caso real que representa ayuda mucho:

    // Solicitamos el precio. El descuento del 8 % solo se aplica a partir de 100 €.
if (precio >= PRECIO_MINIMO) {
    precio -= precio * DESCUENTO / 100;
}

    // Perfil JASP: ser joven Y tener estudios, o bien joven con ingresos altos.
boolean jasp = (edad <= 28 && nivelEstudios > 3)
            || (edad < 30 && ingresos > 28000);

    Explica los saltos

    Un break o un continue sin explicación parece un error. Un comentario de una línea lo justifica:

    for (int i = 0; i < 1000; i++) {
    if (i < 0) {
        continue;            // Ignoramos los negativos, no son válidos para el cálculo
    }
    if (contador == 10) {
        break;               // Ya tenemos los 10 primeros pares, no hace falta seguir
    }
    if (i % 2 == 0) {
        contador++;
    }
}

    9.4. Aserciones (assert)

    ¿Qué es una aserción?

    Una aserción es una comprobación que verifica que una condición debe ser cierta. Si la condición es falsa, el programa lanza un error AssertionError y se detiene.

    Es un mecanismo de desarrollo: comprueba que el programador no cometió errores. En producción se desactivan, así que nunca deben usarse para validar la entrada del usuario.

    Sintaxis

    assert expresión_booleana;
assert expresión_booleana : "Mensaje de error";

    La segunda forma permite indicar qué falla, lo cual es mucho más útil que un error genérico.

    public static int sumaPrimeros(int n) {
    int suma = 0;

    for (int i = 1; i <= n; i++) {
        suma += i;
    }

    // Precondición: el método solo admite positivos
    assert n >= 0 : "n debe ser positivo";

    // Postcondición: la suma de 1 a n es siempre mayor que 0
    assert suma > 0 || n == 0 : "La suma no puede ser negativa";

    return suma;
}

    Tres tipos de aserciones

    Tipo Qué comprueba Cuándo se usa
    Precondición Lo que debe ser cierto antes de ejecutar el bloque. Entradas de un método.
    Postcondición Lo que debe ser cierto después de ejecutarlo. Resultado y efectos secundarios.
    Invariante Lo que debe ser cierto en cada iteración del bucle. Dentro de los bucles.

    Cómo se activan

    Las aserciones están DESACTIVADAS por defecto

    El programa se ejecuta normalmente y no comprueba nada hasta que las activas explícitamente.

    Comando Efecto
    java MiPrograma Aserciones desactivadas (por defecto)
    java -ea MiPrograma Aserciones activadas en todas las clases
    java -ea -cp . MiPrograma Activadas indicando la ruta de las clases

    En Eclipse:

    Run → Run Configurations → Edit → VM Arguments → -ea

    No pruebes tus aserciones sin activarlas

    Si ejecutas el programa con el botón ▶️ de Eclipse sin activar -ea, tus aserciones no se ejecutan y pensarás que funcionan. Compruébalo siempre en modo depuración con -ea.

    public class ComprobacionIMC {

    public static double calculaIMC(double peso, double altura) {

        // Precondiciones: no se puede calcular el IMC sin altura
        assert peso > 0 : "El peso debe ser positivo";
        assert altura > 0 : "La altura debe ser positiva";

        return peso / Math.pow(altura, 2);
    }

    public static String clasifica(double imc) {
        if (imc < 18.5) {
            return "Bajo peso";
        } else if (imc < 25) {
            return "Peso normal";
        } else if (imc < 30) {
            return "Sobrepeso";
        }
        return "Obesidad";
    }

    public static void main(String[] args) {

        double peso = 70;
        double altura = 1.75;

        double imc = calculaIMC(peso, altura);

        // Postcondición: el IMC de una persona está entre 10 y 60
        assert imc > 10 && imc < 60 : "IMC fuera de rango razonable";

        System.out.println("IMC: " + imc);
        System.out.println("Clasificación: " + clasifica(imc));
    }
}

    Lee la traza de pila

    La última línea te dice dónde se produjo el fallo y la primera te dice en qué línea exacta. Esa información es la que te ahorra perder veinte minutos buscando un if mal puesto.

    Cuándo usar assert y cuándo no

    ✅ Úsalo para… ❌ No lo uses para…
    Comprobar que tus cálculos hacen lo que crees Validar lo que escribe el usuario
    Detectar errores de lógica internos Mostrar mensajes al usuario
    Verificar precondiciones de un método Reemplazar un if de control
    Documentar la intención del código Contar como validación de entrada

    El control de excepciones, en la UD07

    Las aserciones son para errores del programador. Los errores del usuario (escribir una letra donde se espera un número, dividir por cero) se gestionan con try / catch, que estudiaremos en UD07 · Gestión de excepciones.
